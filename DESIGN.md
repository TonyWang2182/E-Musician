# Design context

The visual source of truth is [docs/UI_REFERENCE.md](docs/UI_REFERENCE.md) and the user's three images in [docs/design/references](docs/design/references). The DAW workbench inherits their visual language while implementing the revised generic audio/MIDI scope. The 0.5 implementation simplifies the existing Operate workbench; it does not introduce a new token system. Implementation is undergoing integration and native verification: this document does not assert that the new behavior or performance has passed.

Use white paper (`#fefefd`), near-black ink (`#171817`), quiet secondary text (`#626560`) and neutral dividers (`#c6c9c3`). Compact monospaced typography aligns music objects, timings and parameters. Sources use open corners and real waveforms; controls use restrained text, circular transport symbols, fine slider lines and rounded action outlines. Keep time positions exact and reserve a consistent axis. Do not add dashboard cards, decorative patch cables, invented music data, gradients or shadows.

The arrangement is the persistent main workspace. One set of track headers contains names and working Mute/Solo/Arm/Devices controls; the duplicate left track list is no longer displayed. Project actions and a distinct save state occupy the compact header. Add/Edit/Devices/Source/Details and grid/zoom actions form the toolbar. The selected-track/clip inspector can collapse. Audio, instrument and bus tracks share the timeline; audio waveforms and MIDI summaries sit at actual clip positions. A beat/bar grid coexists with exact seconds editing, vertical scrolling, 1–32x zoom, fit and horizontal browsing. Selected clips use a stronger monochrome outline. Clip bodies select without seeking; the ruler and blank timeline seek.

Dragging previews movement or an audio edge trim and commits once on release. Compatible tracks support cross-track movement. Escape cancels a preview and stale revisions reject it. Ordinary edits retain playback; plugin topology changes may stop it. The start field commits with Enter or set, retains an unsubmitted draft on blur and restores the current value with Escape. Source-offset, duration and fade controls use explicit seconds. Editing does not modify source files. The separate source view maps its full source waveform back to the selected clip's project time.

Double-clicking MIDI opens the lower dock, preserving the arrangement above. Its piano-key gutter, beat grid, note rectangles, velocity lane, zoom and optional drum row use real data. First opening fits the actual pitch range. At minimum window height, compact track headers keep two tracks above the dock; compact drum mode shows the step row separately from the piano grid. Close editor restores the full arrangement. Source opens the actual source waveform in the same dock. Dock dimensions are currently bounded automatically, rather than user-resizable.

The dock's SelectedTrackPanel progressively exposes Devices, I/O + sends and Automation. Devices follow the selected track or explicit Master target; native plugin editors remain separate windows and adding plugins reuses the existing catalog browser. I/O offers actual audio/MIDI input IDs, arm state, device-level monitoring, bus output and pre/post-fader sends. Automation enumerates real parameters, displays normalized curve values and current parameter unit text, and commits point edits only on gesture release. Double-click adds, drag moves, Alt-drag adjusts curvature and Delete removes. Master automation is available. Touch/Latch/Write automation recording, sidechain and arbitrary plugin multi-output routing are outside this iteration.

Hover, focus, loading, task progress, missing source/device/plugin, failed import and drag-over states use text and monochrome contours. Unimplemented analysis tabs are removed from the daily workspace. Save immediately shows Saving and tracks its own job; repeated Ctrl+S requests coalesce, failure remains actionable, and edits after the captured revision remain unsaved. Save As checks project identity and takes the current revision after the chooser returns. The footer has one Play/Stop/Record/Loop Transport and master gain. Recording/finalization clearly reports its state and temporarily disables project edits; Stop remains available. Monitoring is explicitly shared by tracks using the same input device. An Agent API exists, but an Agent sidebar is not drawn until implemented.

Waveform peaks load on a background worker and are shared across views; painting never decodes audio. Arrangement draws visible rows and reuses bounded MIDI summaries. The piano roll reuses unchanged shared note snapshots across unrelated project revisions, keeps selection pruning linearithmic and sends small note edits through the incremental command API. These implementation choices require measured performance evidence before stronger speed claims. Native resizing must retain readable labels and usable hit areas; the main window and tool windows own explicit minimum sizes.

The UI uses JUCE-native components, so browser checks do not apply. Verify the workbench at 1000 × 650 and 1280 × 800, including open/closed MIDI, Source and track docks; verify the plugin catalog at 780 × 420 and 900 × 580. Retain standalone PianoRoll component fixtures at 820 × 440 and 1000 × 580, and add compact dock fixtures. Windows 100%, 150% and 200% scaling remain separate acceptance cases.
