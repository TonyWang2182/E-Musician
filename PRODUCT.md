# Product context

E-musician is a Windows desktop DAW built with C++20, JUCE and Tracktion Engine. The current 0.7.0 implementation applies the approved Focus + Mix interface to the existing 0.6.1 production capabilities. It runs independently of Ableton and model services. New projects start at 120 BPM and 4/4. [DESIGN.md](DESIGN.md) records the actual native visual system; [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) records the plan and [docs/CONTEXT.md](docs/CONTEXT.md) records current build and acceptance evidence. Implemented behavior described here is not an independent validation claim.

Arrangement, full Piano roll and Mixer share one project and selection. The selected-track and Master channels remain on the right across all three pages, with real gain, pan, M/S/R where applicable, stereo peak meters and device/details entries. The full Mixer exposes all tracks plus Master. The same parameter changes appear in each view and use the existing Undo history. Double-clicking a MIDI clip still opens a lower editor with Arrangement above; Source and the selected-track Devices / I/O + sends / Automation panels remain available in the lower dock. These docks have calculated size limits rather than a user-dragged resize handle.

Audio, instrument and bus tracks share one timeline. Users can import WAV/MP3 audio and supported MIDI files, create tracks and MIDI clips, rename/reorder/remove tracks, select and move clips across compatible tracks, trim audio, split, copy/cut/paste, duplicate and delete. Clip properties retain exact position, source offset, length and fades without changing source files. Bars/seconds/both ruler modes, fixed/adaptive and triplet grids down to 1/16384, independent Snap, pointer-anchored deep zoom, scrolling, follow and loop/time selections retain their production behavior. Audio keeps its original speed when fixed tempo changes; MIDI uses musical beats.

The real Piano roll supports the full 0–127 MIDI pitch range, pitch fit and scrolling, pencil/double-click insertion, multiple and box selection, movement, note length, velocity, clipboard, duplication, deletion, quantization and transposition. Its optional 16-step drum row edits the same notes; it is not another sequencer model or generated phrase. Instrument tracks require an installed plugin to produce sound. The plugin browser scans Windows x64 VST2/VST3 instruments and effects, targets a track or Master, and manages insertion, native editors, bypass, order and removal. Missing plugins retain stored state and have explicit status. Format support does not assert compatibility with every third-party plugin.

Audio settings expose ASIO/WASAPI, input/output devices, sample rate and buffer size. Tracks retain audio/MIDI input selection, Arm and device-level Off/Auto/On monitoring; tracks sharing an input share its monitoring state. The persistent Transport provides playback, pause/stop, recording and looping, with metronome options and an independent 1/2/4-bar count-in. Audio/MIDI recording retains finalization, one-take Undo and save/reopen/export support. Routing retains bus outputs and pre/post-fader sends. Track gain/pan, Master gain and plugin parameters retain manual automation point/curve editing and Read playback. Recording/finalization protects conflicting edits and keeps Stop available.

WAV export renders the actual mix and plugin chain with sample rate, bit depth, range, tail and optional real-time-rate choices. MIDI export writes selected clips or project MIDI content. Import, project open/save, scan and export expose background job state, cancellation and errors. Save reports completion after file and main-thread metadata commit; repeated save requests coalesce, and edits after a captured revision remain unsaved. New/Open/Close retain Save/Discard/Cancel protection. Projects use schema 4 for stable objects, media, MIDI/controller events, plugin state, recording/routing and automation data. Older schema 1/2/3 manifests are read through migration without rewriting their originals on open; explicit saves retain the existing migration-backup policy. Original source media remain intact. The user explicitly excluded automatic saving and crash recovery from current scope.

GUI, keyboard and external control share EngineSession commands, stable IDs and project/revision checks. The local `--control-stdio` UTF-8 JSONL API supports snapshots and paged reads, idempotent writes, revision conflicts, atomic batches/Undo, events and background job observation/cancellation. `--show` displays that control process's own project; it does not attach to another open DAW instance. The UI consumes snapshots and local gesture previews, with no second writable Edit. Ordinary edits retain the active Edit and playback; plugin topology changes may stop playback. Plugin scanning and offline rendering use child processes; playback plugins run inside the host. See [docs/AGENT_API.md](docs/AGENT_API.md). There is no connected model, Agent business workflow, chat sidebar, separation or transcription engine in this version. Source is an actual waveform inspection view, not a separation result.

The native main window starts at 1280 × 800, with a 1000 × 650 minimum and 2400 × 1600 maximum. The plugin browser retains its 780 × 420 minimum and 900 × 580 initial size. Existing capabilities and new entry points are mapped in [the feature-parity review](docs/review/2026-11-04-focus-native/FEATURE-PARITY.md). The prior 0.6.1 application is preserved at `releases/0.6.1/E-musician.exe`, with its source archive and `archive/v0.6.1-before-focus` branch. Both versions use the same project format and configuration location; use separate saved copies for version comparisons. Historical Keyscape, MIDI/audio recording and mixed-project acceptance remains historical evidence. Actual 0.7.0 GUI focus, third-party plugin windows, device playback/recording, listening and Windows scaling remain separate acceptance items in [the manual short check](docs/review/2026-11-04-focus-native/MANUAL-CHECK.md).

Deferred scope remains automatic saving/recovery, Warp/time stretching, TempoMap, sidechain, arbitrary plugin multi-output routing, Touch/Latch/Write automation recording, chord tools, phrase templates, bundled instruments/soundbanks and Agent model integration. A visual migration does not expand those commitments.
