# Product context — 0.11 workspace

E-musician is an independent Windows desktop DAW with an embedded music Agent. Its Chinese brand is **易乐师**; the application and project identity remain E-musician. The approved bearded, glasses-wearing tree musician identifies the application in the window, Windows icon and startup presentation. Music editing and playback work without a model service or Ableton installation.

**Status, 2026-11-06: the 0.11 implementation, Release build and automated integration passed; physical acceptance pending.** Actual scope and results are in [RESULTS](docs/review/2026-11-06-workspace-brand/RESULTS.md); this does not certify physical ASIO playback, listening, display scaling or arbitrary plug-in loads. ## The daily workspace

The arrangement remains the main workspace. Top controls contain project/save state, transport, position, tempo, metronome and count-in; a second compact row exposes editing, analysis, grid, snap, follow and zoom. The collapsible Library searches native instruments/effects, the installed plug-in catalogue and audio already in the project. It can add devices to an appropriate track or reveal a project audio clip. It is not a downloaded sound library or a cloud marketplace.

A thin overview shows actual clips and the visible timeline range. Clicking it scrolls the arrangement without changing playback position or selection. Track colours identify tracks across headers, clips and overview; a separate outline communicates selection. Track names remain editable. Audio and MIDI clips occupy their real rectangular time ranges, and the arrangement preserves fine-grid zoom, scrolling, cross-track movement and snap editing.

The draggable lower dock hosts the piano roll, source waveform, selected-track controls, analysis or native device editor. One ordered device strip, left/right navigation and one Add button make the selected track's chain accessible. The right Agent sidebar can open or close independently; narrow layouts avoid squeezing the editors by hiding the Library or using an overlay. The footer carries task/device/resource status and master output controls, rather than duplicating transport.

## Music operations

New projects start at 120 BPM, 4/4. Audio/MIDI tracks, buses, sends, audio and MIDI recording, input selection, per-track arm/monitor, looping, metronome, count-in and memory display are implemented. Available audio backends and ASIO operation depend on the installed driver and device. WAV/MP3 and MIDI import, MIDI export, WAV mix export, project save/open and plug-in-state persistence use the existing job and command boundaries. There is no automatic project save or recovery workflow in the requested scope.

The piano roll supports drawing, selection, move/resize, velocity, duplicate/delete, quantize, transpose and an optional drum-step view of the same notes. It can expand to the workspace. Bars and seconds are alternative rulers; the musical grid reaches 1/16384, Ctrl+4 toggles snap, and bar/beat/subdivision labels adapt to zoom. Audio trim, source offset and fades are non-destructive. Fixed-ratio, pitch-preserving Warp can align audio and follow project tempo through background preparation and an atomic edit; it is not a variable-marker Warp editor or a full tempo map.

Native devices are Sampler, a 16-pad Drum Rack, EQ Eight, Compressor, Delay, Reverb and Auto Filter. The 0.11 effect panels provide continuous DSP audition while dragging, one committed edit/Undo per gesture, and cancellation. EQ has a larger response graph and a bounded measured spectrum; Compressor shows measured gain reduction. A/B comparison is local to an open effect panel. Sampler/Rack share the visual controls and real waveform/preview paths, but sample-bank changes still replace playback state and can stop active voices.

Installed x64 VST2/VST3 plug-ins remain available. Scanning uses a child process, but playback plug-ins run inside the host; supported format does not guarantee every third-party plug-in will load, remain stable or expose all parameters. Synthesizers such as Operator/Wavetable/Analog/Drift, comprehensive sampler modulation, Touch/Latch/Write automation recording, arbitrary sidechain/multi-output matrices and commercial-device parity are not delivered by this iteration.

## Analysis and the Agent

Local analysis workers implement real 4/6-stem HTDemucs separation, Basic Pitch transcription with instrument pitch-range profiles, a deterministic expanded-vocabulary chord baseline, and Beat This! beat/downbeat estimation. Profiles are not separately trained transcription models. Chord output is an editable estimate, not guaranteed jazz recognition; beat/meter candidates require correction when uncertain. Heavy work stays outside the audio callback. Candidates retain source identity and become project changes only when accepted: real audio/MIDI/chord tracks, or a beat/tempo/alignment edit without a dummy audio track.

The sidebar supports conversation, current selection context, capability discovery, scoped proposals, confirmation, execution, readback and Undo through the same engine commands as manual editing. Kimi and OpenAI adapters are implemented; other provider slots do not imply working adapters. Keys are private local configuration, never project content. The Agent can inspect structured music/device/analysis data and edit supported parameters. It does not listen to raw audio or judge the audible quality of a result. Simulated-provider tests establish protocol behaviour, not general natural-language reliability.

The desktop uses C++20, JUCE and Tracktion Engine; local Python services handle Agent orchestration and model workers. EngineSession is the authoritative editing boundary, with IDs, revisions, snapshots, jobs and Undo. UI previews do not create a second writable project. Real-time processing performs no network requests, model inference, JSON parsing or file operations. Performance and reliability must be measured against a particular build, device, buffer size and workload; the architecture alone does not establish them.
