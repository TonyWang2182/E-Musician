# Product context

E-musician is a Windows desktop DAW with an explicit control boundary for a future music Agent. The current 0.4.0 implementation focuses on ordinary audio and MIDI editing, installed instrument/effect plugins, project recovery and export. New projects start at 120 BPM and 4/4. Chord tools, deterministic phrase templates and a bundled synthesizer or soundbank are outside this iteration. The development plan lives in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md); actual build and acceptance evidence lives in [docs/CONTEXT.md](docs/CONTEXT.md). This document describes implemented behavior, not an independent validation claim.

Compose is the default workspace. Every real audio or instrument track has a row on one shared timeline, and each clip occupies its actual position and duration. Users can import WAV/MP3 audio and supported MIDI files, create tracks and empty MIDI clips, select multiple clips, move clips across compatible tracks, trim audio, split, duplicate and delete. The inspector exposes exact start time, track gain, pan, mute and solo. Audio clip properties expose non-destructive source offset, length and fades. A single Transport controls playback, position and looping; the tempo dialog changes fixed BPM, meter and loop bounds. Audio keeps its original speed when tempo changes, while MIDI uses musical beats.

Double-clicking a MIDI clip opens a resizable piano roll for drawing, selection, movement, note length, velocity, duplication, deletion, quantization and transposition. Its optional 16-step drum row edits the same MIDI notes; it is not a generated phrase or a second sequencer model. Instrument tracks require an installed plugin to produce sound. The Plugins window scans Windows x64 VST2/VST3 instruments and effects, chooses a target track or master, and manages plugin insertion, native editors, bypass, order and removal. Format support does not assert compatibility with every third-party plugin.

WAV export renders the actual mix and plugin chain with explicit sample rate, bit depth, range and tail choices. MIDI export writes the selected MIDI clips or the project's MIDI content. Import, project open/save, scan and export expose background job state, cancellation and errors; a completed save is reported only after the saved project metadata is committed. New/Open/Close protect unsaved work with Save/Discard/Cancel. Projects store stable objects, source assets, MIDI and plugin state in schema 3, with read-only migration when opening older schema 1/2 manifests. Original source files remain intact.

GUI, keyboard and Agent requests share EngineSession commands and revision checks. The local JSONL stdio API supports snapshots and paged reads, stable IDs, idempotent write requests, revision conflicts, atomic command batches, job observation and cancellation. There is no in-app Agent chat panel or connected model yet. The UI uses read-only engine snapshots and local gesture previews; it never owns a second writable Edit. Ordinary edits retain the active Edit and ongoing playback, while structural plugin operations can stop playback. Plugin scan and offline rendering use child processes, and native plugins loaded for playback still run inside the host process.

Separate currently inspects the selected audio clip's source waveform and maps seeking to the clip's project position. Transcribe remains disabled. Neither page implies that separation or transcription models are running. The user's three reference images continue to define the restrained monochrome visual direction; their chord and phrase-template examples do not define current scope.

The application starts at 1280 × 800 with a 1000 × 650 minimum; the piano roll supports 820 × 440 and the plugin browser 780 × 420. Performance, native input, plugin behavior, exported audio and display scaling must be checked on the built application and reported separately. A source-level implementation or a documentation update does not establish those results.
