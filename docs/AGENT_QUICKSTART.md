# E-musician Agent 0.3 第二批

当前对应 DAW **0.8.0**：助手放在 DAW 内部侧栏，模型网络仍在独立 Python 进程运行。本批新增顺序编辑、规划暂停和执行阶段显示，**实现和本批自动验收完成，待人工桌面短测**。GPT-5-mini和Kimi的小规模真实创建链已通过；具体边界见[验证记录](verification/2026-10-29-agent-batch2/RESULTS.md)。实际界面、中文输入法与 ASIO 听感由用户人工确认；离屏测试和合成焦点事件不能代替真实点击与输入。

## 启动与收起

现有 **0.7.0** 窗口可以继续保留，开发与离线测试不会自动关闭它。准备人工验证时，请用户先保存并关闭旧版，再双击本机快捷入口：`E:\MusicAgent&DAW\Start E-musician Agent.cmd`。启动后确认标题栏为 **0.8.0**；旧窗口未关时，单实例机制可能把请求交给旧版，导致看不到本批新增功能。

工作树也可双击 `Start-Agent.cmd`；它经 `scripts/Start-Agent.ps1` 启动原生 DAW 的 `--agent` 模式。默认产物为 `build/agent-batch2/bin/Release/E-musician.exe`；0.7.0历史产物保留在 `build/sidebar`，两者分开构建。

DAW 工具栏点 **Agent**，或使用 **Ctrl+Shift+A**，打开/收起侧栏。聊天输入时也可用该快捷键收起；Escape 会先关闭展开的模型设置，否则收起侧栏。第一次打开才启动助手；收起保留草稿和任务，工程继续存在。保存工程和退出应用由 DAW 主窗口负责，侧栏没有“关闭 DAW”权限。

在本分支工作树根目录开发：

```powershell
python scripts/dev_agent.py build
python scripts/dev_agent.py test
python scripts/dev_agent.py run
```

默认 Release；需要时传 `--config Debug`。这些入口统一记录构建、测试和运行日志。需要 Windows、Python 3.10+、固定的原生依赖和 WebView2 Runtime；Python 助手本身不需要第三方运行时包。WebView2 SDK 由构建准备脚本固定版本和哈希，运行时缺失与模型配置失败分别处理。

旧命令 `python scripts/run_agent.py --exe PATH` 仍是兼容的独立浏览器/伴随进程入口，连接它自己启动的 DAW；日常使用新的原生侧栏入口。

## 先选范围，再提要求

默认范围是**当前选择**。例如先在钢琴卷帘选中两个音符，再输入“只把当前选中的音符升高两个半音”。助手应列出这两个音符的具体前后变化；点应用后才修改工程。一键撤销本次修改要求期间没有其他工程编辑。

侧栏读取实际的轨、片段、音符和时间区间，切到聊天输入时保留最后音乐选择。发送后若改变选区、轨名、音符或工程，旧方案会被拒绝，须重新生成。助手不会把空选区自动扩大成全工程。

修改全局速度或新建轨时，明确把范围切到**整个工程**，例如“把工程速度改为100 BPM”。这只是授权范围，仍需查看方案并点击应用。修改 BPM 不会自动拉伸音频。

现在可以把相关操作放进一份方案。例如新建测试工程后，切到“整个工程”，输入：

> 新建一条名为测试钢琴的 MIDI 乐器轨，在工程开头创建16个四分音符拍的片段。添加四个音符：MIDI音高60、62、64、67，相对片段起点为0、1、2、3拍，每个长度1拍、力度80、通道1。其他内容不变。

这里的第0拍表示片段开头。助手应按顺序列出建轨、建片段、加音符；核对所有具体变化后点“应用全部修改”。新对象的身份由DAW分配并在方案内关联，用户不需要填写ID。没有加载乐器的MIDI轨仍不会发声；插件由用户手动加载。

每个待编辑 MIDI 片段必须完整读取，当前上限为2000个音符；单方案最多16项动作、2000次音符处理。同一音符在多个动作中处理会累计计入预算。超过上限会提示缩小目标，不默默截断。摘要未显示的选中片段会通过分页补齐，读取期间工程版本变化则停止。当前UI只展示“当前选择/整个工程”；底层clip范围接口未作为第三个产品选项。

## 暂停、应用与撤销

生成方案时点“暂停”，界面先显示“等待暂停”。已发出的模型请求会继续等待返回，随后在下一步或发布方案之前暂停；“继续”恢复规划，“停止”结束后续规划。暂停不等于终止在途请求，也不保证免除该次费用。收起侧栏只隐藏界面，不会自动暂停。

待确认方案可用“放弃”取消。点“应用全部修改”后，后端按“检查→提交→核对→完成”报告阶段，整份方案作为一次原子批次提交；此时不能暂停或取消。阶段显示不表示每条操作分别提交或已经逐条成功。回读成功后可一次撤销整份方案，前提是之后没有其他工程编辑。删除音符和片段同样先写入具体修改清单，须核对后应用。

## 模型设置

已实现 **Kimi** 和 **OpenAI** 适配器；可在模型设置中切换服务、具体模型和对应凭证。Anthropic、Gemini、本地兼容服务明确标为未实现，不能使用。看到“已配置”只代表本机存在凭证，不等于模型权限或网络已验证；运行时不自动回退到另一厂商。

**当前机器已经加密配置两套密钥，无需重新提供或粘贴。** 已有配置为 `kimi-k2.6` 和 `gpt-5-mini`，第一批的历史实测结果不代表本批新能力已通过。在顶部模型名处展开设置即可切换；本批及其他模型、账户、机器的结果须分别记录。

密钥按供应商加密保存于当前 Windows 用户的 DPAPI 文件：`%LOCALAPPDATA%\E-musician\agent\moonshot.key` / `openai.key`。模型偏好分别保存，切换不会覆盖另一服务的密钥。仅在日后更换密钥或配置其他机器时，也可以使用隐藏输入：

```powershell
python scripts/run_agent.py --provider kimi --configure-key
python scripts/run_agent.py --provider openai --configure-key
```

不要把密钥放进命令行参数、源码、工程或 Git。OpenAI 使用官方服务端点，可沿用机器已经配置的 loopback 代理；应用不安装代理或修改系统网络。模型名称以实际账户支持为准。

## 当前支持的操作

规划器提供19种编辑动作，只读查询另算：

- 查询已提供的工程结构、选择对象及按需读取的 MIDI 信息。
- 工程速度、轨名、轨道音量/声像/静音/独奏，须符合所选范围。
- 新建音频/乐器/Bus轨；在既有或本方案新建的乐器轨上创建 MIDI 片段，并可继续添加明确音符。
- 复制、移动（含同类型轨道间）、裁剪和删除片段。
- 在范围内添加或删除音符，移动起点、调整时长、移调、起音量化（含1/16384）和力度。
- 一次原子批次应用、状态回读和受版本保护的一步撤销。

新增音符需明确音高、起点、长度、力度和通道；助手没有附带固定乐句模板。裁剪只能缩短到当前片段内部的区间，含CC等MIDI控制器事件的片段暂时拒绝Agent裁剪，避免改变边界控制器状态。删除片段不等于删除磁盘素材。

当前不生成/理解音频，不控制任意插件、录音、保存或删除文件，不提供自动保存/恢复或长期自主创作。保存和重开仍由用户在DAW操作。回读成功说明数据符合方案，实际声音仍需试听。

## 费用、数据和异常

每次要求最多4次模型请求，每次最多2048输出token；界面显示实际返回的请求/token计数，不推算未知价格。没有自动付费重试。取消阻止后续步骤，已经发往服务的请求可能仍收费；失败请求不一定能取得token用量。

模型接收要求、近期对话、有界工程结构/选择和按需 MIDI 统计/少量示例。音频文件、插件预设、本机文件路径不随这些请求上传；完整音符在本地处理。模型私有推理状态仅用于当前调用循环，不进入界面、对话记录或审计。

方案绑定工程ID、音乐revision和选区revision。超时可能发生在 DAW 已收到命令之后，因此写通道停止且不自动重放；先查看 DAW 的实际状态。助手断开不会关闭工程。关闭侧栏只收起；需要退出时在 DAW 正常保存并关闭。

审计位于 `%LOCALAPPDATA%\E-musician\agent\audit.jsonl`，保留当前及轮转的有界元数据日志，包含任务/方案ID、摘要哈希、版本和结果；不保存密钥、完整对话、音符或模型思考。这不是工程恢复文件。

## 人工验证怎么做

统一构建完成后，用空工程或测试工程副本，先试上面的建轨→建片段→四音符方案，再做一次整体撤销；随后检查复制后修改只影响副本、裁剪/删除目标是否准确，以及暂停→继续和过时方案拒绝。真实点击聊天输入框与钢琴卷帘，检查Space、Ctrl+4、Ctrl+Shift+A和中文输入法；最后用自己的声卡、插件和工程试听。由用户操作实际界面，不使用computer-use代替人工验收。
