# ADR 0001：原生引擎与控制边界

日期：2026-10-26（Asia/Shanghai）

状态：接受；M1 实施中，兼容性和性能待实测。

关联：[开发计划](../DEVELOPMENT.md)、[架构](../ARCHITECTURE.md)。

## 背景

项目需要独立 Windows DAW、Separate/Transcribe/Compose 三工作区及 Agent Sider。音频播放必须持续稳定，编辑需要统一状态、撤销和保存；模型任务具有不确定耗时。Ableton 控制脚本提供组件与反馈方面的参考，但不是可移植的 DAW 音频引擎。

## 决策

1. 以 C++20 + JUCE + Tracktion Engine 实现原生应用与音频基础，固定经过验证的依赖版本。采用现有引擎不代表已实现完整 DAW，也不预先保证设备兼容性或性能。
2. 三工作区共享一个工程与 Transport。引擎 Edit 持有音乐状态；应用元数据补充来源、候选与稳定标识，不重复维护另一套权威音乐模型。
3. 工程修改通过单一命令/工程控制入口。GUI、Agent 和控制器映射复用语义；读取使用快照与事件，批量编辑按需要分组撤销。
4. 实时音频/MIDI 调度与工程命令、IPC、模型推理分离。外部服务不能直接进入音频回调或任意修改 Edit；所有发布遵守引擎线程与生命周期契约。
5. Ableton Python/M4L 保留为可选适配器；独立 DAW 不要求安装 Ableton。适配器能力与目标版本分别验证。

## 影响与验收

- 降低从零编写音频宿主的起步工作量，同时接受引擎接口、依赖升级和许可路径的约束；发行准备按实际依赖另行确认。
- UI 与 Agent 可复用编辑逻辑，但需显式设计对象 ID、版本冲突、撤销、状态回读及错误结果。
- M1 先验证固定依赖的原生构建、应用启动和音频输出；后续分别验证保存恢复、GUI/Agent 同语义、失效目标拒绝及一次撤销。
- 模型超时或服务不可用时，已具备的本地播放应继续运行。性能结论必须来自固定负载、设备与构建配置下的测量。

## 重新评估条件

若关键设备、授权路径、工程语义或可测性能无法满足目标，记录具体证据后提出接替本 ADR 的新决策；不以一次失败构建或未验证的预期推翻边界。
