# ADR 0002 — WAV/MP3、多轨工程与素材归档

日期：2026-10-26。状态：采用，实现与验收分开登记。

## 本轮目标

用户在确认下一阶段计划后要求加入 MP3 并继续构建。本轮交付目标是 WAV/MP3 多轨试听、每轨混音、可保存并重开的工程及基础撤销；完整编排、模型与 Agent 保持原阶段边界。

## 决策

- 启用固定 JUCE 版本内置的 MP3 解码器。AudioSource 先逐帧扫描 MPEG Layer III，取得真实帧数，再顺序解码到 24-bit PCM WAV 缓存。波形和 Tracktion 共用该 PCM；原始 MP3 用于工程归档。用户运行程序不需要 FFmpeg 或编码器。MP3 导出不在本轮范围。
- 缓存位置为 JUCE userApplicationDataDirectory 下的 `E-musician/cache/audio-v1/<源文件 SHA-256>.wav`。按源内容寻址，验证缓存格式/长度/首尾读取；新解码逐块检查有限采样与写入结果，写后重验源哈希，通过临时文件提交。缓存版本随解码规则变化升级，当前不自动回收。
- 该准备层来自首轮实际测试失败：JUCE 8.0.6 对无 Xing 索引的 VBR 使用首帧码率估算时长。保留严格时长测试，改用帧扫描及顺序解码，避免应用播放依赖近似 MP3 seek。当前保留解码器 padding，未做 gapless/编码器延迟裁剪；拒绝 free-format、截断帧和中途改变格式的流；元数据上限 32 MiB，单个 PCM 缓存小于 4 GiB。Xing/Info 与 MPEG-2/2.5 分支已实现，尚缺独立兼容性样本矩阵。
- 每个导入文件建立独立音轨，当前片段从工程 0 秒开始。Edit 是活动音乐状态的权威；应用只维护稳定 ID、素材路径及解码信息缓存。保存 DTO 和撤销历史从 Edit 读取，不建立第二个可任意修改的活动模型。
- `.emproj` 为严格校验的 schema 1 JSON；配套 `<工程名>.assets/<代次 ID>/` 保存原始 WAV/MP3 副本。所有素材引用为受限相对路径。移动工程需一并移动清单和 assets 目录。
- 保存先复制到新素材代次，再写同目录临时清单并替换正式清单。失败时保留上次清单和素材。旧代次暂不自动删除，避免清理失误损坏已保存工程；去重与回收另做。
- 打开工程先检查清单、素材及解码并构建候选 Edit，全部成功后切换。失败导入、批量导入或打开不会清空当前工程。
- 保存只提交磁盘快照，当前播放会话暂时保持原文件句柄；删除原文件前应重新打开已保存工程以使用归档副本。后续改为后台素材归档/重新绑定时单独验证播放连续性。
- 采用最多 64 步内存快照撤销，支持本轮音轨和混音操作；拖动增益合并为一步。结构变化及撤销重做会停止播放并重建 Edit；保存和工程切换不进入撤销历史，历史不跨应用重开。
- dB 值经过引擎推子曲线转换会产生浮点微差，保存/脏状态比较规范到 0.001 dB，避免撤销回已保存状态仍被误判为修改。
- 当前最多 64 条音轨是输入边界，不是性能承诺。加载、归档复制和候选构建仍在控制线程；大工程的后台操作与性能验收留到后续。

## 验证要求

真实 CBR/VBR、单/双声道 MP3 解码与非静音渲染；中文和大写扩展名；坏文件与混合批次失败；静音/独奏/增益的真实渲染差异；保存重开 ID/混音一致；移走测试源文件后使用归档；搬移完整工程；缺素材/坏 JSON/保存失败保留原工程；Undo/Redo 与未保存状态；界面实机流程。

结果写入开发日志与本轮 verification，未执行项保持待验证。后续片段位置、裁剪、MIDI、插件等新增持久状态必须升级 schema 或明确迁移策略，不能静默丢弃。
