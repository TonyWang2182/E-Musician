# ADR 0003 — 共轴多轨编曲总览

日期：2026-10-26。状态：采用，功能验证独立登记。

## 问题

0.2.0 能播放多轨，但中央区域只显示选中轨道，Compose 仍禁用。用户在完成上一轮手工验证后反馈“不能在编曲视窗里看到所有轨道”。保存工程确有多轨，问题属于视图表达。

## 决策

- Compose 启用为默认音频编曲总览，Separate 保留单轨细看，Transcribe 继续保持未实现状态。此次不将“总览”称为完整编曲编辑器。
- 每轨一行，使用同一秒坐标、水平缩放、滚动及播放位置。片段宽度取自身真实时长；短轨之后保留空白。垂直滚动使所有轨道可达，不为塞入固定高度而无限缩小轨道。
- 轨道点击更新既有全局选中 ID 与 Inspector；时间区域点击/拖动只调用 seek。选轨、缩放、滚动、页切换均为视图操作，不更改工程 revision、音频混音、撤销或持久化。
- TrackSnapshot 暴露只读 waveformSource。WAV 指向原 PCM，MP3 指向 AudioSource 已验证的 PCM 缓存。原 source 继续用于显示及归档。ArrangementView 不持有可写 Edit，不独立推导 MP3 时长或重新编码。
- 波形峰值在后台准备，绘制使用完成的缓存；以轨道 ID 维护行身份，素材变化才重建来源。可见区绘制与播放线更新须有边界，不能在 paint 中解码整段音频。
- schema 1 不变，既有 CL.emproj 可直接打开。当前所有片段仍从 0 秒开始；移动、裁剪、分割、多片段轨道及音乐网格另行实施并迁移持久化格式。

## 验证

使用真实组件事件验证选轨/定位/切页与不脏工程；检查长短轨比例、窗口尺寸、缩放、滚动和空态。现有引擎渲染/工程恢复继续回归。用户 CL 工程仅加载和截图，不保存、不播放；前后文件哈希核对。具体结果见 [本轮验收](../verification/2026-10-26-arrangement/RESULTS.md)。
