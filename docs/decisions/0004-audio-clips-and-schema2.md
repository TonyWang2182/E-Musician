# ADR 0004：音频片段与 schema 2

日期：2026-10-26。状态：采用，本轮实现通过限定验收，见 [验证记录](../verification/2026-10-26-clips/RESULTS.md)。

## 原因

schema 1 将轨道等同于从零开始的完整音频文件，无法保存片段移动，也无法表达后续分割共享素材。此次先交付同轨横向移动，裁剪、分割、跨轨移动和复制留待后续。

## 决策

- 工程包含素材与轨道；轨道包含片段。素材保存稳定 ID 和原文件路径；片段保存稳定 ID、assetId、时间线起点、源偏移和长度，单位为秒。同一素材可以被多个片段引用，保存时每个 asset ID 只归档一次。
- 活动位置仍从 Tracktion Clip 读取，控制层只补充稳定身份和不可变来源。DTO 是保存、候选装载和撤销的快照，不是第二个可写引擎。
- `moveClip` 校验预期 revision、对象存在和时间范围，保持源偏移与长度，停止播放后修改位置。工程长度与循环范围取全部片段的最远结束处。上限遵守固定 Tracktion 版本的 48 小时，不依赖引擎静默截断。
- 拖动期间只有界面预览，释放鼠标才提交一次命令；Escape 取消，过期的手势拒绝提交。一条移动命令对应一步撤销；精确秒数输入使用同一命令。
- schema 2 记录 assets 和各轨 clips；快照、内容比较、Undo/Redo、候选 Edit、保存与重开共同覆盖新字段。时间脏状态按纳秒比较，避免浮点区间减法造成假修改；该精度不代表视觉或音频设备延迟保证。
- schema 1 只读装载后在内存生成确定的素材/片段 ID，以完整已解码素材长度补齐旧片段。打开不修改清单和素材。显式覆盖旧清单之前保存逐字节 `.emproj.schema1-<UUID>.bak`，旧素材代次保留；备份失败则不替换原清单。恢复时将备份复制回原清单文件名，保留同名 assets 目录。
- 素材检查仍使用统一 AudioSource：MP3 的播放与波形引用相同 PCM 准备源，归档保存原 MP3。片段移动不复制、裁切或重编码原素材。
- 当前没有独立未引用素材库；schema 2 不接受未引用 asset，防止装载后静默丢失。允许空轨，片段/素材数量保护上限为 4096、轨道为 64；这些不是性能承诺。

## 验收和代价

测试必须实际渲染 WAV、48 kHz CBR MP3 与 44.1 kHz VBR MP3 的延迟片段：前 8 秒静音、之后输出与原片段对应；Undo/Redo、保存新会话重开及源偏移都要一致。旧工程迁移和失败场景只操作自有副本，真实 CL 工程保持原样。

控制线程导入/打开/保存和历史恢复仍可能阻塞；保存后活动源仍绑定导入路径，重开才使用归档。原始文件与旧归档代次的自动管理、音频导出、裁剪和分割不在此次范围。
