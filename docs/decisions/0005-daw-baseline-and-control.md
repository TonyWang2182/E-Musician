# ADR 0005：通用 DAW 基础、增量编辑及本地控制

日期：2026-10-26。决定已实施，具体构建和验收状态以 CONTEXT 为准。

## 需求

用户将本轮收敛到通用 DAW：不做和弦工具、乐句模板或自有音源；新工程120 BPM；Windows x64 VST2/VST3并行支持；未来Agent调用真实接口；普通编辑应保持播放和无关插件实例。先前文档的 Chords/模板/测试音源不再是当前交付目标。

## 选择

1. 活动状态仍归 Tracktion Edit。命令生成临时候选 DTO 校验，应用时按稳定ID增量更新同一个 Edit；打开/新建才替换整工程。GUI、快捷键和Agent共用命令语义。
2. 工程自有ID、素材引用、片段类型和插件槽元数据进入同一 ValueTree Undo。固定版 Tracktion 的 `AutomatableParameter::setParameter` 同步附属值时使用空 UndoManager，因此音量/声像和外部参数使用明确的标量 UndoableAction；不能假设调用引擎setter即有Undo。参数动作按稳定ID找回目标，不持有跨工程裸指针。
3. 插件拓扑变化是可停播的结构操作；普通片段/音符/混音编辑和对应Undo保留实例。删除前将原生插件状态缓存到被删除的ValueTree，缓存本身不进Undo，避免晚些Undo重建实例时丢失当前音色，也避免用保活大量插件占住样本内存。
4. 单个后台重文件任务拥有不可变DTO和文件。准备/哈希/MP3解码在worker，主消息线程提交引擎。导入/打开对身份和版本做晚到检查；保存/导出不覆盖期间的后续编辑。完成状态代表主线程提交已结束。
5. 插件扫描与WAV渲染各在独立子进程，限制结果大小、超时和取消。扫描失败不回退主进程加载。运行中的VST仍在DAW进程内；本轮不宣称插件实时沙箱。项目渲染使用固定快照和临时输出，成功且目标指纹未变才替换。
6. schema3扩展MIDI拍点/音符、固定速度拍号、循环/声像/淡化和插件二进制状态。schema1/2只读迁移，覆盖前保留原清单备份。源素材不被非破坏编辑修改。
7. 本地控制显式以`--control-stdio`开启，不监听网络。写请求含身份/预期版本/幂等ID；读快照和音符/片段/目录/参数分页，有限队列隔离慢读端。事件、任务、幂等账本都有明确上限。
8. 音频回调不执行应用JSON、文件、模型或控制服务操作。性能报告保留真实设备参数、负载和测量缺口；输入对象上限不作为性能保证。基础长跑与第三方插件兼容测试分别记录。

## 结果与限制

插件和音频线程不再因普通Undo重建整工程。代价是需要分别验证ValueTree操作、标量参数Undo和原生插件状态恢复。DTO校验和快照仍有与项目规模相关的工作量，密集MIDI和连续参数编辑需单独测量；不能只用16轨WAV证明所有负载。

会话内容键在Windows使用系统CNG `BCryptHash`，目标链接`bcrypt`；非Windows及原生调用不可用或失败时回退JUCE SHA-256。两条路径保持同一摘要及内容键语义，不改变工程格式，也不把哈希移入音频回调。源码指纹`4053c3e9eeecae100fc2df4033463a4986a1d5b3a3a140f9f6cbc4f791085507`的[Release回归](../builds/20261026T170557.840637Z-3c78b14072.json)包含CNG/JUCE参考等价检查，[10万音符控制测试](../builds/20261026T170525.513639Z-4f33e20459.json)也通过原50ms P95预算。后者测量停播、无插件、单片段10万音符条件下的stdio命令往返，不代表物理GUI延迟、实时音频回调或长跑验收。

MIDI只支持固定速度/拍号、SMF0/1 PPQN及音符；不支持的表达、控制器和速度图明确拒绝，只有用户或Agent显式 notes_only 才忽略。MIDI通过用户插件发声。录音、32位插件桥接、复杂路由、自动化曲线及真实分析模型继续单独排期。

## 重采样源定位补充（2026-10-27）

决定：音频片段使用`sincMedium`，并在固定Tracktion提交 `b0c7dd090a56b27fe01bb394617891906eb34daf` 上维护一个明确的HQ reader seek补丁。补丁进入仓库，bootstrap应用、CMake核验；原文件/结果/差异的LF SHA-256和单一目标路径见[依赖记录](../DEPENDENCIES.md#hq-sinc-源定位补丁)。补丁已应用并通过当前Debug/Release音频回归，更广采样率矩阵及实时长跑仍待验证。

两次失败分别保留，不能通过加大样本误差阈值掩盖：

- [Lagrange回归失败](../builds/20261026T154316.823288Z-12b0af4eed.json)：`build/smoke/Debug/08415fa35437`中的44.1kHz VBR夹具复制1.5秒后，与48kHz基准对应区间最大差约0.006098、RMS差约0.001549；同率WAV/MP3差为0。只读逐块分析显示256帧块之间约−0.2725/+0.81输出样本的周期性变化，排除4096个比较样本后仍存在。上游Lagrange将每块源帧数取整并据此修改比率，形成持续调制。
- [sinc回归失败](../builds/20261026T155226.500167Z-884268c3a4.json)：`build/smoke/Debug/c231e90acd46`中的trim对比最大差约0.001664、RMS差约0.000676。逐块偏移稳定在约−0.2178输出样本，区别于前述持续调制。trim起点0.25秒的首块从11776输出帧开始，44.1/48kHz映射需要10819.2源帧，底层整数seek丢失0.2源帧，对应−0.217687输出样本。一次固定相位校正后残差降至约1e-6，仅用于定位原因，不作为测试通过条件。

补丁保持源相位的方式：目标源坐标为`q`，当前输入/输出步长为`r`；取整数`anchor = ceil(q - 256 * max(1, r))`，重置已有SRC，以`256 / (q - anchor)`的临时输出/输入比率生成256帧丢弃前缀，再用`src_set_ratio`立即恢复真实比率。固定版libsamplerate保留输入相位和历史，因此实际输出从`q`开始。该方法不搜索公共周期，互素采样率也不会退化成数秒预滚；seek不分配内存，复用既有256帧缓冲。最大sinc半滤波长度小于143源帧，前缀覆盖medium/best所需历史；源读取失败或SRC不支持的比率明确返回读取失败。

没有选择修改StoredClip源偏移：这种补偿会依赖块大小及seek位置，破坏工程坐标语义。也没有固定将所有MP3转成48kHz作为修复：切换设备或导出采样率后仍可能重现问题。

应用补丁后，Debug与Release回归均4/4通过，分别保留[Debug音频报告](../../build/smoke/Debug/ab9fcfa12259/daw-report.json)与[Release音频报告](../../build/smoke/Release/ae529f5d8934/daw-report.json)。当前44.1kHz VBR夹具经`sincMedium`渲染到48kHz，原trim区间、复制后对应源区间及256/512帧块基准渲染的最大样本差均为0；比较沿用原`2e-5`阈值，没有作测试端相位补偿。当前回归还包含split、跨轨、Undo和工程保存重开，不能据此推广到未覆盖的比率与质量组合。

正反向全部采样率与medium/best矩阵仍未覆盖；重复seek、文件起点等边界也需扩展组合验证。实际设备上的预滚成本和持续播放长跑仍待测。脚本保护、相位算术及上述短音频夹具均不替代这些验收，本项不宣称已满足完整实时性能目标。
