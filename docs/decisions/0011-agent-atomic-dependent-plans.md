# ADR0011：原子依赖方案与可暂停规划

日期：2026-10-29。状态：已实施并通过本批自动验证，实际桌面/听感待人工。对应DAW 0.8.0 / Agent 0.3；不把第一批验证结果提升为本批通过。

## 问题

第一批方案只能引用已有轨/片段，用户必须先应用创建、再发起下一次要求。直接允许模型猜新ID会削弱身份边界；逐步写入真实工程又会留下部分成功状态，难以一次撤销。任务进行中还需明确区分规划暂停、原子提交和已提交后的回读失败。

## 决定

采用一次确认、一次原生batch。Python在只读快照的临时候选上模拟顺序动作，输出真实可审阅的前后变化和最终检查项；EngineSession继续拥有唯一Edit。候选是暂存计算数据，不能作为另一个可写工程或后台自动恢复系统。

原生子命令可用 `as` 声明 `[A-Za-z][A-Za-z0-9_-]{0,39}` 别名，只能引用此前成功建立的正确类型结果。只有create_track、create_midi_clip、单源duplicate_clips产生引用；track_id/target_track_id接受轨引用，clip_id/clip_ids[]接受片段引用。其他字段不插值。别名不跨批次，不能重用、前向引用或在批次末尾指向已删除对象；轨/片段的实际ID始终由引擎生成。

原生保留逐命令候选校验和整批最终校验，全部通过后一次应用；候选失败不触碰活动工程，不发布临时引用。有效提交与已有GUI手势划清Undo边界，候选失败不结束手势。成功result返回refs与executed_commands；可选结果输出参数不破坏已有三参数execute调用，也避免全局旧结果泄漏。通过batch_result_refs及版本1能力声明让客户端在写入前拒绝不支持的程序。

Python编译器在同一候选中追踪别名、派生片段和音符UUID，选择约束在每一步执行，不能仅靠提示词保证范围。复制MIDI时原生首先重建独立片段/音符/控制器ID，随后同批write_notes建立本地已知音符UUID；write_notes/edit_notes保留控制器。Agent暂拒带控制器的MIDI裁剪，避免假装已模拟原生边界控制器追踪；DAW原生能力保持。

单方案最多16项动作、2000次音符处理，每个待编辑片段完整读取最多2000音符；原生仍有100条批次命令和工程输入边界。缩小的产品预算不能通过依赖引用绕过，摘要截断不能冒充完整目标。当前厂商仍为Kimi/OpenAI，未增加其他Provider。

暂停只作用于规划：在途请求完成后等待，恢复重新检查工程/选区。派发和发布与暂停/取消使用同锁边界，等待发生在worker；原子提交不能暂停或半途取消。旧状态GET带任务generation，过时结果不能覆盖新任务或设置状态。

未取得提交回执时按结果未知处理，停止不明写通道且不重试。已知成功提交但回读失败时保留回执、明确已提交；Undo取得成功回执即消费该撤销目标，不能因回读失败再Undo。数据回读不代表音色、听感或创作质量验收。

## 边界与代价

没有采用多次真实写入组成的长事务，也不在失败后静默重放或猜测修复。当前批次大小有界，不是无限自主任务。候选模拟和原生校验会增加非实时控制开销，最终性能须测量，不以算法描述冒充通过。

网络/模型位于独立Python worker；JSON、快照和命令在非实时控制线程处理，音频回调不执行这些工作。原生回归覆盖引用类型/顺序、生成ID、复制控制器、失败原子性、请求幂等及Undo/手势；Python回归覆盖候选/范围、暂停取消边界、已提交回读失败和旧GET。本文记录实现决策，测试是否通过以本批统一记录为准。

## Windows助手启动补充

本机实际出现文件虚拟化：现有会话文件的resolve结果落入Codex包LocalCache，但尚未创建的ready仍显示逻辑AppData路径。比较二者物理父目录会误拒同一个原生会话。现按原生传入的逻辑绝对路径校验ready为精确同目录同名后缀，并拒绝会话、ready和临时文件符号链接。真实helper启动/正常退出由EmbeddedHelperStartup覆盖，不启动DAW或调用模型。异常仅记录阶段、类型、栈位置与路径形状，不记录异常字符串、能力令牌或凭证。


## Undo/Redo的原生基线

真实消息循环发现EM_PROJECT和首次懒建SCENES引发根节点排序；Undo还原非规范基线后，延后的MoveChildAction会清掉Redo。宿主现在在初始化/装载阶段提前建立这些容器、规范顺序，然后清理基线历史。批次自身的延后初始化更新保留在同一事务；下一显式操作照常分界。没有修改共享Tracktion依赖，没有生产嵌套消息泵，也没有按时间禁止真实Undo操作。最终测试包含异步等待后的单Undo/Redo、原生126条与真实客户端13条。
