# 分析进程的资源准入与故障隔离

状态：0.12.1 已实现，自动测试证据见 [本轮结果](../review/2026-11-06-generation-stability/RESULTS.md)。

本机生成音频的分离日志出现 CUDA OOM，随后同进程转 CPU 又发生分配失败。另有无结果文件的原生异常，具体崩溃堆栈未知。决定让宿主拥有分析进程树和失败终态，禁止在失败的 CUDA 上下文内隐式搬模型到 CPU 重跑。

Windows 子进程挂入私有 Job Object 后才恢复运行，仅继承指定日志/输入句柄；退出、取消和严重资源压力都回收该进程树，记录退出码。模型加载前检查系统提交余量及物理余量，Worker 另加已知音频缓冲预算；运行时检测持续低提交余量。阈值是防护策略，不是模型峰值预测。所有探测、等待、文件与模型工作仍在后台，不进入实时回调。

原生线程完成前释放持有的过程资源，再公布 done，避免消息线程为尚在析构的捕获对象等待。UI 显示可选中、可滚动的简短失败原因；失败结果不能被导入，原件和工程保持不变。当前没有修改分页文件、终止用户其他程序或自动云端回退。

生成 Agent 从新鲜工程快照取得 BPM、拍号、播放头与合理默认时长；小节换算由适配器完成。模型负责音乐描述与选工具，默认值不覆盖明确指令；明确导入确认仍保留。不同项目速度的生成请求不能通过默认策略悄悄改变工程速度。

云端 MIR 准备工作与本次修复分开：安装文件不等于远程 Provider 已接入。后续本地/云端切换需能力登记、输入上传、结果校验、共享 GPU 调度与重连语义，再开放给手动界面和 Agent。
