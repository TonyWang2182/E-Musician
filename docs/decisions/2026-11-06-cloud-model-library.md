# 云端模型库独立于生产任务路由

日期：2026-11-06。状态：已实施部署层；生产调度与 DAW 接入留待后续。

## 背景

用户要求同时部署需要的云端生成和分析模型，当前不下载大型文件到 E 盘，不接入 DAW。已有 ACE 网关、SQLite 任务队列及本地 MIR 正在使用，不能因为新增模型而改变其依赖或隐式替换工作流。

## 决定

- 每个模型单独固定源码、权重、运行环境和验证清单；仅共享经校验的下载缓存，不升级其他环境。SheetSage2 保留其 Python 3.11 / Torch 2.8，其他模型使用各自已验证组合。
- `deployment.json` 分开记录文件校验、环境、CPU 加载、GPU 推理；`catalog.json` 只是汇总，不是生产 Provider 注册表。MuScriptor 权重受限则保留受阻状态，不使用占位结果代替。
- GPU 探针串行申请共享文件锁，读取 ACE 队列和空闲显存，监测中断条件，仅终止自己创建的进程组。此机制服务本轮评测，不宣称实现多模型常驻或生产资源调度。
- 新权重与音频只留云端；本地 Git 保存部署脚本、版本锁、小型验证记录与原始日志索引。脚本运行期间不可覆盖，重试使用新文件名，保留失败与实际运行 SHA。
- 后续接入必须新增明确的任务适配和资源调度层，再复用现有不可变候选、明确接受、工程资产与 Undo；音频回调不参与网络或模型推理。

## 结果与代价

五个新增模型通过受控短推理，MuScriptor 仅公共源码和环境通过；当前 DAW 功能未因此增加。环境会占用额外磁盘，但版本冲突和回滚边界清楚。完整歌曲、识别质量、长音频、并发和本地云端切换仍需各自验收。模型版本与实际测量见[部署结果](../review/2026-11-06-cloud-model-library/RESULTS.md)。
