# 显式逐轨监听与录音独立

状态：已实现，自动验证通过，物理演奏及听感待验。证据见[本轮结果](../review/2026-11-15-bm-midi/RESULTS.md)。用户明确要求只有Monitor On才听到实时键盘，Rec只决定相应轨道是否录音，不允许轨间相互影响。

界面只提供Off/On；旧Auto输入兼容为Off。Monitor是轨道运行状态，不根据Rec自动打开，也不因选择轨道改变。多个On轨共用同一输入时允许有意叠加；多个Rec轨允许多轨同时录音。实际写入仍由全局录音开始/结束以及现有每目标录音上下文负责。

统一命令以track_id确定目标；旧input_device_id仅在唯一轨道引用时兼容，歧义时在修改前失败。不会通过修改输入设备的全局Monitor开关实现逐轨操作。设备全局状态在装载/初始化时由控制层明确设定，GUI/Agent使用同一命令路径。

关闭一轨监听、更换或移除该轨输入时，清理只针对该轨的实时输入来源；不向其他目标广播note-off，不以全局panic或重置所有插件解决挂音。既有MIDI片段来源应继续回放。所有路由/编辑状态修改在控制线程执行，实时线程不增加网络、JSON、文件或阻塞工作。

与Tracktion固定版本的改动保存为仓库patch及精确哈希，测试覆盖实际Hosted输入/PCM/录音数据，而不仅是监听布尔值。物理键盘、驱动和插件听感验收另列。


快速 Off 回归证实，仅调用 restartPlayback 会让异步替换前的旧图继续接受 NoteOn，留下未释放声音。控制命令在重建该 Edit 后同步处理待发布图，再报告完成；受管空乐器轨使用稳定的输入节点，目标释放数据随该目标传递。该修复由真实 PCM、NoteOn/Off 计数和双轨隔离断言验证，不以布尔状态代替声音结果。

录音或收尾期间保留既有修改保护：需先停止，再切换输入、Monitor 或 Rec。MIDI 1.0 同通道同音高的实时音符与片段声音是否能独立释放，仍受具体乐器声部实现限制；源感知诊断乐器验证不能扩大为所有第三方插件的保证。
