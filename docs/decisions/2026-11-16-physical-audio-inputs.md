# 物理音频输入、设备身份与回调通道映射

日期：2026-11-16。状态：已采用，Release/离线与M-Audio短录音验证见[结果](../review/2026-11-16-audio-input/RESULTS.md)；不代表所有物理声卡均已测试。

## 问题

输出优先初始化使JUCE默认输入数量为零；旧设置界面提交当前活动通道，无法从零开启输入。Tracktion逻辑输入启用不等于硬件物理通道启用。此外固定版本的Windows驱动回调按活动通道打包，而引擎WaveInput使用物理索引；仅启用第二路时需要显式映射。不同设备的通用Input 1名称也不足以保存稳定路由。

## 决策

1. Settings明确编辑物理输入掩码和单声道/立体声配对草稿，Apply通过统一命令，提交后回读实际状态。当前卡保留用户选择，新卡默认前两路单声道。输入全部关闭是合法状态，Arm/Monitor会解释为何不能使用。
2. 公共音频输入ID由驱动、设备名称和物理通道身份生成；TE内部ID不向调用方作为路由依据。旧未限定设备的ID要求重选。不是硬件序列号，操作系统重命名设备可能需要重选。
3. 设备变更在控制线程验证、应用、回读，失败恢复先前实际掩码，不能依赖JUCE可变默认通道数。变更前先断开物理音频轨目标并同步发布图，避免新卡启动回调时沿用同名旧目标；完成或回滚后仅恢复仍匹配设备身份的目标及Arm状态，MIDI目标不改。设备操作期间阻止重入和录音冲突。
4. 驱动控制面板遵循设备能力；消息队列调用，窗口使用SafePointer。厂商嵌套消息循环返回后重新取得设备/窗口，不使用旧指针。
5. 固定引擎补丁在prepareToStart预建打包索引到物理通道的映射，回调只复用数组；兼容完整物理槽的空指针，缺失输入清零。实时线程不分配、不读写文件、不调用网络。

## 验证边界

合成驱动必须覆盖零输入恢复、稀疏In2、设备同名通道、配置拒绝回滚、控制面板重入、真实PCM录制与旧MIDI隔离。物理M-Audio检查单独记录，麦克风来源和听感不能从非零底噪推断。其他型号的硬件兼容性保留人工验收。
