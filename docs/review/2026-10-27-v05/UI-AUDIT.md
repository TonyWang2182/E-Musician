# 0.5 UI复盘与简化方案

日期：2026-10-27（Asia/Shanghai）。状态：只读复盘完成；后续已按授权实施本轮子集，见末尾实施记录，统一构建与原生验证由根任务记录。

复盘方法：原生JUCE界面的源码、既有实际渲染截图和官方DAW手册对照；沿用impeccable Operate/distill原则。初始复盘阶段没有运行应用、OS输入或网页检测器，也没有改动产品源码、PRODUCT或DESIGN；授权后的实施和文档更新另记在末尾。本会话context由根代理统一加载，不重复启动。此报告不等于真实鼠标、硬件录音或DPI验收。Questions skipped：现有需求和项目上下文足够确定本轮方向，硬件与故障信息由根代理统一询问。

## 结论

现有界面的主要问题不是功能少，而是同一任务跨越多个菜单、窗口和重复的轨道区域；保存过程缺少稳定、独立的状态，允许重复点击并让错误覆盖进度。应把“选轨—录音/编辑—听回放—保存”放在一个主编曲窗口中完成，精细设置按需展开。保留白底、近黑、等宽文字和细线的已有风格，不复制其他DAW的配色或堆叠全部专业控件。

不能用UI简化掩盖保存失败。保存状态机和数据管线修复优先于布局改造。

## 推荐的新主窗口

1. 一条全局控制栏：工程名、保存状态、Save；播放/停止/录制、位置、120 BPM、4/4、循环和节拍器。只保留一套Transport。新建、打开、另存为、导出和设备设置放常规文件/设置菜单，常用命令仍有快捷键。
2. 主体是单一轨头＋编曲时间轴。取消重复的左侧轨道列表；轨头含名称、类型、Mute/Solo、录音预备、监听、紧凑电平及音量；选中轨显示更多输入信息。重命名可双击轨名，右键集中轨道命令。
3. 左侧可选浏览器：音频文件、乐器、效果；默认为关闭或窄面板，不重复列轨道。拖入音频自动建轨；拖入乐器到空白区建立乐器轨。已有轨的“＋乐器/＋效果”直接打开过滤过的插件选择。
4. 底部Dock：MIDI编辑器/音频详情/设备链，根据选择切换。双击MIDI只打开该区，保持上方至少两条轨道可见。Dock有清楚的收起、放大、弹出入口；弹出是可选高级行为。
5. I/O、发送、自动化按需展开在当前轨道或详情区。高级路由不常驻占据每条普通轨的全部面积。主输出保持可见；bus/return有明确类型和接收路径。
6. 未接入的Transcribe从常用导航移除，Separate的当前真实能力改名“源音频”，成为音频详情，不继续让用户误认已支持分轨。模型功能将来接入后另设计入口。

尺寸建议是实施起点：轨头约220–260px；折叠浏览器与详情时，1280宽主窗给时间轴至少约850px。1000×650时默认收起浏览器，底部Dock可切换/放大而不是把网格压到不可操作。采用可拖分隔条和边界约束；所有滚动区域保持同一轨道行对齐。最终数值需按实际截图验证。

保留当前纸白/近黑/灰色设计。录音、错误、选择状态优先用清楚文字和轮廓区分；如果引入红色，只用于录制/削波等语义，不以颜色作为唯一反馈。主操作建议使用“保存、录制、添加轨道、乐器、效果、输入、输出、监听”等清晰中文，插件原名和参数原名保持原样；不能混入开发实现术语。

## 保存交互契约（与管线改造一起落地）

状态必须独立于全局提示文本：未保存、正在读取插件状态、正在归档新增素材、正在提交、已保存、失败。工程名旁显示当前状态和最近完成时间；任务详情展开后才展示素材计数、耗时和错误详情。只在主线程最终提交成功后显示已保存。

点击Save后立即进入保存中反馈，并先让界面显示该状态，再进行必须在主线程的插件状态采集。普通编辑保持可用；保存中的再次Save不重新采集大块状态，合并为至多一次“保存当前后续更改”的意图。若期间没有新修改，重复点击不创建任务。保存后的新修改继续显示未保存，不能被旧任务清除。

失败保留工程与旧目标，并就地给出重试/另存为；无关的旧busy错误不能覆盖当前保存进度。取消需要解释实际边界：可取消阶段尽快终止，已经进入不可分割提交时不伪装成取消成功。保存用于关闭/打开其他工程时，等待该保存代次的最终结果，而不是等待任何save任务结束。

## 六条优先验收流程

设备设置增加明确的驱动类型（含实际可用ASIO）、设备、采样率、缓冲、启用的输入/输出通道和MIDI端口。显示实际协商值与设备报告延迟，不把请求值当成功结果；ASIO控制面板作为设备旁的次级入口。当前 `MainComponent.cpp:1605` 的AudioDeviceSelector输入最小/最大均为0，MIDI输入选项也关闭，因此录音实现必须同时接通设备层和UI，不能只加一个Record按钮。切换设备前明确处理正在录制的take，失败保留原工程并报告恢复结果。

| 流程 | 验收重点 |
|---|---|
| 用户报告的两音频＋插件MIDI保存 | 自有副本/同规模场景；只点一次能完成；连点10次不启动10次归档；状态不被旧错误遮挡；保存后重开音符、插件音色和素材一致 |
| 从空工程写第一段MIDI | 添加乐器轨后可直接选乐器/录音或画音符；双击片段在Dock编辑；不用关闭另一个工具窗才能看时间轴 |
| 多轨音频录音 | 选择真实输入、Arm指定轨、设监听、全局Record、Stop后片段出现；记录状态/电平反馈；丢设备或磁盘失败有可见恢复路径 |
| MIDI录音 | 明确输入设备/通道与乐器；录制和回放音符准确；停止后无悬挂音；一次Undo撤销录制结果而非丢失其他轨道 |
| 自动化与bus/send | 曲线与片段同轴；一次拖动一步Undo；Mute/Read等状态明确；轨到bus、发送到return的目标可见；循环路由被拒绝时指出涉及轨道 |
| 小窗与性能 | 1000×650/1280×800、100%/150%/200%DPI分别看；所有轨可达；选轨、滚动、插件窗开关和保存期间仍可反馈。测事件到可见反馈，不以组件回调或JSON往返替代 |

新增录音、ASIO、自动化、路由的按钮必须连接真实命令、状态、Undo和工程保存。未完成的能力应不提供可点击假入口。所有UI继续读取快照、提交统一命令；音频回调不得因界面状态、曲线绘制或保存进度加入JSON/文件操作。

## 实施文件边界建议

- `MainComponent.*`：主窗口分区、保存状态、Dock生命周期、菜单和录音/I-O/插件面板协调；把大型PluginPanel/ValueForm逐步抽出，避免继续增加一个万能组件。
- `ArrangementView.*`：统一轨头、局部控制、自动化lane、共同滚动/时间轴、选择和拖动；不成为第二个工程模型。
- `PianoRoll.*`：作为可嵌入组件复用，首次内容适配音高、保留视口、剪裁绘制、手势提交；普通选轨不重新复制所有音符。
- 独立AutomationView/TrackControls/DevicePanel（如实施需要）：只持只读状态和手势预览，稳定ID发命令；生命周期由Main统一管理。
- 引擎、存储、插件状态和录音数据管线由对应模块实现；UI不直接调用插件getState、复制素材或执行录音文件写入。

实施次序：保存状态/管线与故障复现 → 主编曲/轨头/编辑器Dock → 真实录音入口 → 自动化/路由逐步展开 → 本机设备与整条操作链验证。此文的前半部分是复盘和实施提案，具体实施范围与验证状态见下文。
