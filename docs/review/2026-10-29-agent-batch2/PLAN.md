# Agent第二批：常用编辑与连续依赖任务

日期2026-10-29；基线55f06b7033e65f125d1635c42c0c43fb52e298c8。当前状态：实现中。用户“开始做第二批”按前述Agent第二批解释；本次不同时扩展长期DAW底座的Warp、侧链和冻结轨道。

## 交付范围

1. 复制、裁剪、删除片段、跨轨移动；添加/删除MIDI音符、修改时长，复用原有移调/量化/力度。
2. 方案内部按依赖引用新轨/新片段；本地预览完整最终结果，用户一次确认，原生一次原子提交和Undo。模型不直接执行原生命令，不新增插件/保存/录音权限。
3. 规划阶段暂停/继续/取消；执行阶段显示检查、提交、回读阶段。原子提交不能中途取消；失败/超时不盲目重复写入，回读失败仍说明是否已经提交。
4. 修复旧工具说明和选择上下文不一致，以及并发空闲GET回写陈旧UI缓存的竞态。
5. 记录计划、变更、失败、原始日志、构建指纹、验证与人工清单，提交既有功能分支，不自动合并main。

## 分工和接口

原生代理负责EngineSession batch refs与回归；计划代理负责plans/selection和纯Python回归；UI代理负责web与headless测试。根负责runtime/server/bridge、原生集成入口、构建和交付档案。每个文件有单一修改方，不覆盖用户既有DEVLOG及6条启动摘要。

batch子命令可用as创建别名，后续ID字段以@别名引用；仅此前成功声明的正确类型可用。实际ID由原生引擎生成，成功返回refs和executed_commands。复制MIDI后的write_notes使用本地UUID，保留原生复制得到的控制器；全部仍在同一个候选事务，未逐步发布到实时引擎。

模型最多16动作/单片段完整读取最多2000音符，保留预算和冻结范围。当前音符选择不能授权整个片段/其他轨；目标对象、最终位置、音符和时长均需校验。GUI/Agent仍复用命令与唯一Edit；音频回调不引入网络/JSON/文件工作。

## 验收

- 新轨→新片段→明确音符一次应用、一次Undo。
- MIDI复制→克隆音符修改，原片段不变，控制器保留；裁剪边界/删除/跨轨符合预览。
- 错误别名、前向引用、类型混淆、后一步无效、过时选区/工程全部拒绝；失败不改变音乐revision/Undo。
- 原生回读确认真实ID、对象数量、位置和完整音符；缺失/伪造结果不得报成功。
- 暂停不新发模型请求、不应用；取消能退出暂停；恢复时再次检查工程/选区。
- 模型/UI/原生回归、现有DAW CTest；最终源码冻结后统一跑，原始记录入build-logs，摘要入docs/builds。
- 已授权真实API仅少量合成工程测试，分离模拟阶段用量；不上传用户音乐。
- 旧0.7程序正在运行，不关闭它；独立build/agent-batch2（或同等独立输出）避免覆盖锁定EXE。用户负责实际GUI/IME/声音检查，禁止computer-use。

## 暂不扩展

音频分析/生成、任意插件控制、自动保存/恢复、长期后台自主创作和新供应商接入。本批明确音符写入属于编辑能力，不声称音乐质量已验收。
