# DAW 0.7.0 / Agent 0.2 第一批：人工短测

状态：人工检查待用户执行。构建、CTest 5/5、Python 178 项和原生侧栏 23 项已通过；GPT-5-mini 与 Kimi-k2.6 的真实联网合成工程编辑、回读和撤销也已通过，见[本批验证结果](../../verification/2026-10-29-agent-sidebar/RESULTS.md)。这些结果不代表真实桌面操作、中文输入法或物理声卡播放已验收。这里只检查本批新增体验，不重做旧版整套录音验收。使用测试工程副本，记录应用版本、模型服务/模型名和每项结果；不要把 API 密钥放进反馈或截图。

**先保存并关闭已有0.6.1或其他旧版窗口。** 通过 `E:\MusicAgent&DAW\Start E-musician Agent.cmd` 或工作树 `Start-Agent.cmd` 打开本批版本，确认标题栏显示 **0.7.0**。否则单实例机制可能仍进入旧版。默认产物为 `build/sidebar/bin/Release/E-musician.exe`，不是旧 `build/bin`。点击工具栏 **Agent** 或 **Ctrl+Shift+A** 开关助手。准备一条已有至少4个音符、能正常发声的 MIDI 轨；当前机器两套密钥已加密配置，无需再次提供。

1. **两个音符的范围与撤销。** 双击片段打开钢琴卷帘，只选中两个音符；Agent 保持“当前选择”，输入“只把选中的两个音符升高两个半音，其他内容不变”。核对方案目标与前后音高再应用。应仅改变这两个音符，时值/力度及其他音符不变；点“撤销这次修改”应一次还原。若计划范围不对，不应用，记录显示的范围。
2. **拒绝过时方案。** 再生成同类方案，先不应用，回钢琴卷帘换成另外两个音符，再点应用。应提示选择已变化，不能改旧或新选区。另生成一次，手动改轨名后再应用，应因工程变化拒绝；随后重新提要求可以继续。
3. **切换模型。** 空闲时打开顶部模型设置，检查 Kimi 的 `kimi-k2.6`、OpenAI 的 `gpt-5-mini` 均已配置。切换后新请求应显示对应服务/模型，原待确认方案应失效；未实现服务不能执行。两个服务的真实调用已自动验证，本项重点检查切换体验，可留到第6项使用另一个服务，无需另外增加付费请求。其他服务或模型未执行就记录“未测”。
4. **收起、展开与草稿。** 在输入框打几行尚未发送的内容，点工具栏 Agent 收起，再展开；草稿应保留，工程和选区仍在。在聊天输入框内再试 Ctrl+Shift+A，侧栏应收起；用同一快捷键重新展开。若模型正在处理，收起不应取消任务或关闭工程；展开可看到实际结果。关闭 DAW 仍走原保存/退出流程。
5. **文本焦点、快捷键与中文输入。** 实际点击聊天输入框，输入带空格的文字，Space 应输入空格且不触发 DAW 播放；用中文输入法组词、选候选，Esc 取消候选时不应误收起，确认候选后再用 Ctrl+Enter 发送。输入框获得焦点时试 Ctrl+4，确认没有误切 DAW 吸附；实际点击回钢琴卷帘后，Space 应能控制播放，Ctrl+4 应切换网格虚线/实线。收起并展开后也检查一次，确认没有残留的输入焦点保护。检查窄侧栏下按钮、输入、方案和模型设置仍可使用。
6. **明确全工程范围。** 将范围切为“整个工程”，要求“把工程速度改为100 BPM”。核对方案后应用，检查速度变化，再撤销恢复。切回“当前选择”，应显示选区范围；全局操作不能静默扩大范围。音频不会随 BPM 自动拉伸，不以这项检查判断音频变速能力。
7. **实际播放与查询并行。** 播放平时使用的测试工程，在侧栏提交一次简短查询；期间拖动播放位置、缩放并收起/展开侧栏，检查响应与声音。记录是否卡住、断音、退出，以及实际声卡、采样率、缓冲、轨数/插件和大致时长。停止后正常保存副本并重开，确认工程仍可使用；无需重做整套录音验收。

遇到失败时记录具体步骤、预期/实际、界面错误和是否已应用；不要反复点应用。超时后先看 DAW 实际内容，避免重复修改。模型请求被取消或失败仍可能产生费用，测试结果只填写实际观察。

原生离屏检查使用合成 `focusin` 事件，验证网页监听、原生事件桥和快捷键保护；它没有通过真实鼠标点击取得操作系统焦点。原生组件截图也无法捕获 WebView2 子 HWND 的全部网页像素。上述自动结果及浏览器合成截图都不能替代人工界面、输入法和 ASIO 听感检查。未执行项保持“未测”，不要沿用旧版的设备结论。
