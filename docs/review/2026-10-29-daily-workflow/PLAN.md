## 优先级与交互约定（待实现）

### P0：用户明确需求

1. **标尺、网格和剪辑对齐一起做。** 默认音乐主标尺，提供小节/秒切换，可选双标尺。单位不改变吸附状态，不改音乐内容或播放位置。独立提供 Snap、固定网格精度和自适应模式；缩放时区分刻度标签密度与编辑精度，过密格线可隐藏但必须显示实际吸附精度，放大后落点应与细分线重合。固定网格不因缩放改变。考虑三连音及片段边缘吸附，吸附候选优先级需确定且可预测。拖动预览目标位置/长度，保留 Alt 临时绕过；多片段移动保持相互间距。
2. **小节输入贯穿常用参数。** 片段起点/长度、循环起点/长度可按小节拍或秒查看和输入，不能只改顶部标签。拍号分母应参与显示换算。项目仍使用固定 BPM；切标尺不等于音频变速或 Warp。
3. **节拍器和预备拍作为同一组录音准备控件。** 放在 Transport 的 BPM/拍号附近；节拍器开关和录音预备拍独立。预备拍开关记住所选 1/2/4 小节，倒数由音频引擎驱动，完成后从指定录音位置开始。需覆盖小节中间起录、工程零点、不同拍号和中途取消。节拍器声音不进入内部录音素材或离线导出；主输出静音/停止时的行为必须明确。
4. **内存与运行状态。** 状态栏显示进程工作集 RAM（含同进程插件），详细提示可补私有提交量；不冒充每个插件独立用量。建议配音频 DSP 负载、xrun 掉音计数及实际采样率/buffer。计数用于排查，不等于每次增加都已人工听见爆音。

### P1：对照后建议补齐的日常动作

这些是新增建议，不把“计划”记成用户已验收，也不挤占 P0：

- **剪辑效率：** 编曲框选、时间选区、Ctrl+C/X/V、多片段跨兼容轨移动；音符剪贴板与可见画笔模式；片段淡入淡出拖柄。保留已熟悉的 S、Ctrl+D，菜单展示对应快捷键。
- **循环与导航：** 可拖循环两端/整体、选区一键循环、按拍/小节跳转、播放跟随开关；用户手动滚动/编辑时不抢视口。命名定位点可放在这组后段。
- **录音/混音反馈：** 轨道输入/输出及 Master 电平、峰值保持/过载提示；区分无输入、未监听、插件无输出等常见状态。

## 实施边界与验收

- 保持单个权威 Edit。音乐编辑、节拍器/录音设置经 EngineSession 命令；视口、标尺和网格属于编辑器偏好，不因切换而把工程标为未保存。工程级新字段如需持久化，应明确 schema/迁移及 Agent capability，而不是只增加 GUI 临时变量。
- 共享拍/秒/采样换算与网格策略，不让 Arrangement、PianoRoll、Inspector 各算一套。批量剪辑维持稳定对象 ID、一次 Undo 和不重复复制媒体的约定。
- 预备拍需要引擎时钟与录音状态机：空闲→预备→录音→收尾。预备期间 Stop 可取消；不能使用 UI Timer 延时后才调用 Record 来假装精确同步。原始首音、持续到首拍的音符及踏板边界需有明确处理和回归。
- RAM 初拟每秒采样，CPU/xrun 低频展示，电平采用有界快照。不得为刷新数值重建音频图、遍历全部片段或在音频回调查询操作系统内存；不能将整体工程快照以高频重新序列化。
- 自动检查重点：格线/落点映射、多拍号与非整数 BPM、缩放和单位切换不改数据、成组编辑/Undo、预备首拍边界/取消、节拍器不进导出、保存重开。自动与人工证据分列，构建仍走 dev.py/Recorder。
- 人工短测：拖音频和 MIDI 到同一小节→切秒显示后再拖→框选/复制/循环；开节拍器和一小节预备录一段→检查首拍、声音与保存；连续播放时检查资源显示是否稳定。每轮只安排相关检查，不重跑已通过的完整混合工程验收。
- 最小窗口 1000×650 保留可操作性，继承当前黑白风格。代码、组件测试与用户视觉/听感分别验收；本计划不代表新功能完成。

建议顺序：网格/标尺与剪辑一致性 → 节拍器/预备拍 → 资源显示 → P1 剪辑、循环与电平反馈。先做到日常编曲顺手，再考虑已暂缓的扩展。
