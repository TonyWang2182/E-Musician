# Kimi 音乐 Agent 首个可用闭环

日期：2026-10-29。基线 `7f7eb65`（DAW 0.6.1），独立分支 `feature/kimi-music-agent`。用户授权使用所提供的 Kimi API 凭证开始构建；本文件不包含凭证。

## 本轮交付

1. 官方 Kimi Provider；Windows DPAPI 本机凭证、超时和调用预算，不自动重试付费请求。
2. 独立本地助手窗口，通过现有 JSONL 控制它启动的 DAW。一个 Edit；不自动附着另一个窗口，不更换实时引擎。
3. 读取工程和按需读取 MIDI → 模型提议 → 确定性校验/前后预览 → 人工应用 → 单批次提交 → 回读验证。修改冲突时重新提议。
4. 首轮开放速度、轨名/音量/声像/静音独奏、新轨/空 MIDI 片段、已有 MIDI 移调/量化/力度及片段移动。模型不执行 shell、任意文件操作、录音或插件操作。
5. 任务取消、一次撤销、中文错误、调用/token 计数；元数据审计与开发证据。未经量测不宣称低延迟或全部音乐任务完成。

## 责任边界

- Provider/密钥：`scripts/music_agent/provider.py`、`secrets.py`。
- 动作编译/校验：`plans.py`。
- 根协调：bridge/runtime/server/启动脚本、集成测试、文档/交付。
- UI：`web/`，沿用黑白编辑工作台风格；不使用电脑控制查看用户桌面。
- 文档记录计划、实现、自动验证与人工验收分别进行。测试和启动经 `scripts/dev.py` 的 Recorder。

## 验收

- 模拟 Provider 的确定性回归：未知命令、非有限参数、过期工程、重复应用、取消、撤销保护、恶意文本、凭证泄露与 HTTP 访问边界。
- 现有 Release EXE 的隔离离线 JSONL 集成：真实状态变更、MIDI 内容回读、一次 Undo；不打开物理设备，不修改用户工程。
- 官方 API 最小真实请求单独记录；失败也记录，不以模拟通过替代联网通过。
- 用户最后只需开助手并完成一个小工程的“提出修改—预览—应用—撤销”听感/GUI检查。

## 本轮范围外

生成音频、分离/转录、自由插件操作、复杂多 Agent 调度、长期记忆、自动保存/恢复与内嵌 JUCE 聊天栏。后续以已验证的权限/工具协议扩展。
