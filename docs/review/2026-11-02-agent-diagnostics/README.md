# Agent 意图与 API 排查手册

## 一段话说明工作原理

内嵌侧栏把你的文字、当前工程和选择交给独立的 Python 助手；助手通过配置的模型 API 读懂目标，必要时读取音符或原生装置状态，生成一份可查看的方案。程序会在本地核对目标、范围、参数与工程版本，把操作转成 DAW 的统一命令，用户点击应用后提交，再回读结果；音频线程不调用模型或联网。装置有没有被列入工具、当前选择范围、读取到的参数，以及模型本身都会影响结果；模型不能听到音频，也不能操作尚未开放的装置。

## 这次发现并改进

1. 原来只改一个 EQ / Compressor 参数，也要求模型完整生成设备所有参数（EQ 有八段），容易遗漏或改错。本轮提供局部参数动作：模型提供设备、参数和目标值或变化量，本地按工程最新快照保留未改参数并转成原命令；仍有范围、版本、完整校验、预览和回读。
2. 每次最多模型调用从 4 次提高到 6 次，单次输出上限从 2048 提高到 4096 token，可给多次读取和较复杂方案更多空间。最大用量和潜在费用相应增加；不是每次必用满。
3. Compressor 的 dry/wet 可以读取和调整；旧存档没有该字段时按 100% wet 解释。新增 Stereo Delay、Reverb 和 Auto Filter 的 Agent 参数契约；Auto Filter 的低／高通模式是枚举，LFO 开关是布尔值，其余参数为数值。新增原生装置不会凭名称自动获得编辑能力：还需要引擎提供参数与状态契约、Agent 接入验证、回读和测试，不能只在提示词里声明。

## API 检查结果与限制

- 本机配置检查显示当前选择 OpenAI、模型 `gpt-5-mini`；OpenAI 和 Kimi 均有已保存凭证，适配器标记支持工具。**有凭证不代表它有效、有额度或当前网络可访问**。
- 已审阅 OpenAI Responses 和 Kimi Chat Completions 的请求构造、工具返回、错误与限额处理，并用模拟请求/响应回归。按用户授权对当前 OpenAI / gpt-5-mini 发出一次不含工程内容的真实健康测试，成功返回指定工具调用，使用 136 输入 / 18 输出 token（[记录](../../builds/20261102T074521.451380Z-77e82c1367.json)）。这证明测试时基本连接、凭证和工具调用可用，不证明复杂音乐意图理解；Kimi 未做本轮真实联网测试，其他时间的额度或网络状态也可能变化。
- 当前 Kimi K2.5/K2.6 适配器明确关闭 thinking。本轮 OpenAI 的已知兼容推理模型新增低／中／高三档设置，默认中；旧配置缺字段时自动按中处理。未知或不兼容模型不会发送推理强度参数。高强度可能增加等待和 token 消耗，也可能触及当前 45 秒请求超时或 4096 输出 token 限制；不能保证音乐理解正确。参数含义见 [OpenAI 官方推理模型文档](https://developers.openai.com/api/docs/guides/reasoning)。
- API 返回 401/403 检查平台账户和密钥权限；429 检查用量与速率；404 检查模型名及权限；网络超时检查连接和服务状态。不要向聊天或日志粘贴密钥。若密钥曾被分享，应到对应平台撤销并重新生成，再在本机重新配置。

## 建议用一份空白工程逐项测试

每一步记下原话、所选模型、选择范围（selection / clip / project）、当前选中轨或装置、完整提示和是否出现方案。不要在文档或截图中写 API 密钥。

1. **只回答**：问“工程现在有几条轨道、速度是多少？”若无法回答或出现网络/鉴权错误，先排查 API 和侧栏连接；能正确回答只说明文本和快照基本通畅。
2. **精确意图**：选择一条轨，让助手“把选中轨道音量设为 -6 dB”。方案应显示目标轨及数值；应用后检查轨道并撤销。若目标不是所选轨，停止应用并记录当前范围。
3. **原生 EQ 单参数**：在该轨打开 EQ Eight，设置第三段为 250 Hz、0 dB，然后说“把当前轨 EQ 第三段提高 3 dB，其他参数保持不变”。方案应只改变第三段增益，应用后核对其频率与其他七段，最后撤销。
4. **压缩器变化量**：在有 Compressor 的轨上说“把压缩器阈值降低 3 dB，其余参数不变”。先记录旧阈值，确认方案里的新值等于旧值减 3；播放和听感由你判断。
5. **主轨和采样器范围**：对主轨效果器、Sampler/Rack 参数先将范围切到 project / 整个工程；采样器一次只请求一项。若显示后台准备，等待完成和回读；超时或结果未知先检查 DAW，别反复提交。
6. **复杂或含糊的要求**：记录它是正确追问、提出不完整方案，还是自信地做错。对比把同一句拆成明确目标/数值后的表现；不能仅凭一次结果判断模型总体能力。

可用以下格式报告问题：`模型 + 原话 + 选择范围 + 当前轨道/装置 + 预期行为 + 实际回复/方案 + 是否应用 + 错误文字`。先用独立工程，不覆盖原项目。

## 开发接口验证

- Python 纯模拟回归按 `scripts/dev.py` 的 `Recorder` 执行；覆盖协议格式、范围、局部参数、版本冲突、异步完成和回读。模拟通过不证明真实服务理解自然语言。
- 原生变更必须提供可枚举的类型、参数范围、设备身份、实际读取与受版本保护的写入；需要对应方案、界面、序列化、undo、回读、离线/实机测试。当前 DAW 发布版本化效果器和乐器能力目录，Agent 将其与自己的类型、参数范围、频段和读写限制核对；缺失或不一致时相关操作明确不可用。宿主创建类型和目录使用共享注册清单；参数声明仍需开发者同步，并由真实 DAW 状态与目录的端到端测试检查，不能声称新增设备无需接入即可自动可控。
