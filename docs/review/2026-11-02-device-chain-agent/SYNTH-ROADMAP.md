# 后续原创合成器路线与工程边界

状态：**以下均为未实现计划**。参考 Operator、Wavetable、Analog、Drift 的功能类型设计 E-musician 原创装置，不声称复刻 Ableton 的算法、音色、预设或完整功能，也不把单一振荡器包装成四款成品。

## 共用基础先行

- 现有 `NativeInstrument` 只注册 Sampler / Drum Rack；`ProjectStorage` 只接受这两种内置乐器，现有 `prepareBank` 和异步任务假定存在 pads 与音频素材。新增合成器需为不同类型提供独立状态及验证、可演进版本/旧工程兼容、真实宿主创建和恢复，不能仅在列表增加名称。目前每条 MIDI 轨只允许一个 instrument。
- 构建共享 MIDI 和多音色实时骨架：按 block 内采样偏移处理 note-on/off、声部上限与抢占、包络释放、all-notes-off；再逐项加入 sustain / pitch bend 等并定义行为。音频回调不得网络、读盘、解析 JSON、加锁或堆分配；参数要平滑，参数快照和声部状态须满足线程边界。
- 把 UI、保存状态、撤销、离线渲染和 Agent 的读写统一到真实设备身份与版本化参数契约。现有 Agent 对原生乐器仅支持已加载采样参数、禁止创建；需另行实现合成器创建、参数读取/局部修改、审阅、范围校验、实际回读和设备目录覆盖测试。**Agent 参数命令不等于自动化曲线**：要支持曲线，还需为宿主暴露稳定、可枚举且带单位的自动化参数与实时更新路径，验证保存/回放/导出一致。

## 四类乐器的最小真实版本

1. **FM / Operator 类**：多振荡器和明确的相位调制路由，至少可设置各振荡器频率比、调制深度及包络；验证不同路由确实改变频谱，并处理高频折叠、反馈与声部释放。固定单个波形不构成可用 FM 装置。
2. **Wavetable 类**：可审计的内置波表数据及位置扫描，带限/分级波表和表间插值，至少可调位置、音高与包络；测试扫描连续性、高频折叠和各采样率下的稳定性。仅循环单个波形不构成完整波表合成。
3. **模拟减法 / Analog 类**：至少两种真实产生的振荡波形、混合、滤波器、振幅包络和基本调制；带限振荡器与滤波器共振边界应可测。UI 清楚表明路由和音频来源；不要承诺模拟电路或商业插件同音色。
4. **Drift 类**：建立在真实减法合成之上，增加可控、可复现测试的声部漂移/失谐和调制；漂移需限制范围，随机源与声部生命周期明确。仅把同一减法合成器换个名称不足以表示完成。

以上是各类首版的下限，并非 Ableton 全功能清单；波形、调制源、矩阵、效果、MPE、预设和复杂音色库需另行确定与实现。

## 分阶段验证

1. 单元与 DSP：每种音色离线产生非零输出；音高/频谱、幅度包络、复音、note-off、弯音/踏板、失控输入与非有限数测试；多采样率和不同 block size 不失稳，不在回调内分配。
2. 宿主闭环：轨道创建、同轨效果链、不同装置切换、参数边界、可听渲染、旁路、一次撤销/重做、保存重开、离线导出和旧工程兼容；缺失或不支持的状态显示明确错误。
3. 自动化与 Agent：按稳定 ID 查目录、创建、读写、相对调参、作用域及版本冲突、审阅/提交后回读；自动化曲线变动能实测改变播放和导出，不能只验证曲线数据存在。
4. 实际设备：标明机器、采样率、buffer、运行声部数、轨道及效果器负载，记录 CPU、xruns、延迟和长时间运行；MIDI 键盘、ASIO、GUI 与听感由用户验收。未测之前不得声称高性能或等同商业装置。

参考：[Live 12 乐器手册](https://www.ableton.com/en/live-manual/12/live-instrument-reference/)；本地现状以 `apps/desktop/NativeInstrument.*`、`apps/desktop/EngineSessionNative.inc`、`apps/desktop/ProjectStorage.cpp` 和 `scripts/music_agent/native_catalog.py` 为准。
