# 原生采样器与鼓组 Rack 迭代计划

状态：首版实现及离线验证通过，实体设备、GUI 和听感待人工；详情与未解决限制见 [RESULTS](RESULTS.md)。以现有未提交的监听/插件修复为基线并保留原文件和日志；这并不代表这些修复已通过真实设备验收。

## 目标

- 简易采样器：将用户指定的音频加载为乐器，可用 MIDI 演奏并导出，提供音高映射、样本播放范围、增益和基本包络；展示真实素材与状态，明确空音源和错误。
- 鼓组 Rack：16 个 MIDI pad，单 pad 分配独立样本，以音符触发，提供各 pad 音量、静音和可见映射；能在 MIDI 片段与真实键盘上工作。
- 沿用项目黑白线框、等宽文字与既有设备入口；交互直接修改同一个工程，经版本校验和可撤销命令，保存并重开工程后可复原。素材管理须明确原文件、工程可移植性与缺失处理，不能只显示占位 UI。
- Agent 接口遵循已有工程控制命令、快照与版本语义；未经实现与测试不声称模型能直接操作新装置。

## 工程边界与验收

优先审查固定版本 Tracktion Engine 可复用能力与许可，记录技术选择；素材解码/准备和磁盘操作不放在实时回调。GUI 不持有第二套可写工程；同步、撤销、工程切换和缺失文件需验证。首批明确支持范围及容量限制，复杂切片、时间伸缩、多层采样、音色库不冒充已实现。

测试按层分别记录：确定性样本及 MIDI 离线渲染（音高/不同 pad/静音/力度）、保存与重开、撤销/重做、无效与丢失样本、旧工程兼容；组件布局和控件行为；最后由用户进行实际音频设备、键盘与听感验证。性能声明须有设备/采样率/缓冲/负载/测量方式，不从构建通过推断。

具体端到端：独立临时工程生成合成 WAV，建 MIDI 轨并添加采样器/Rack，等待后台 ready，写 MIDI 音符后导出 WAV 检查实际非零信号；保存、复制工程 bundle 并隐藏原文件后重开和再次导出；覆盖 pad 增益/静音、Undo/Redo、样本替换/清空、坏文件与并发保存保护。导出和重开均必须使用真实引擎，不以 DSP 函数或 UI 测试替代。旧 0.8.0 程序无法识别含新原生装置的工程，人工测试必须另存新工程。

## 任务分工

引擎代理研究并实现采样器；Rack 代理研究并实现鼓组及复用；界面代理保持既有风格；主代理协调集成、验证、文档和构建日志。代理共享工作树，避免覆盖已有未提交修改及其他代理编辑。每次构建/测试使用 Recorder，原始输出保存在 build-logs，摘要在 docs/builds，DEVLOG 只追加。
