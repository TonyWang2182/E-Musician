# 0.9.0 人工短测

状态：待用户验收。自动模型测试和离线宿主测试不能代替本机声卡、鼠标、真实音乐听感。

## 打开正确版本

关闭已有 E-musician 后，双击 `E:/MusicAgent&DAW/Start E-musician 0.9.0 Analysis.cmd`，确认窗口标题为 **0.9.0**。旧版入口 `Start E-musician 0.8.1.cmd` 保留。

先用新工程。建议素材：`E:/MusicAgent&DAW/analysis/cache/public-fixtures/vibeace-excerpt.wav`（短混音）、`trumpet-excerpt.wav`（独立音高乐器）。同目录有原始来源、署名和许可；这些不是完美分离或准确转录的标准答案。

## 手动分析

1. 导入短混音，选中音频 clip，点顶部 **analyze**。下栏应出现 separate / audio to MIDI / chords。`from / s` 从当前片段开头算，`length / s` 是分析长度；也可先在编曲窗选时间范围，再打开 analyze，检查范围是否正确。
2. 在 **separate** 点 **run analysis**。等待进度，界面应仍能响应；可拖动视图、查看轨道和工程信息、保存当前工程。未导入的候选不随工程保存，导入后要再保存。首批只允许一个重分析任务；录音前先完成或取消分析。
3. 完成后在结果列表选中 vocals、drums、bass、other，分别点 **play stem** 试听。试听流送到当前音频设备，固定 -12 dB，不启动时间线；点分析面板内的 **stop** 应停止试听，关闭下栏也会停止由该面板发起的试听。若没有输出设备，先在 audio settings 中选择。听感需自己判断串音、尾音与瞬态。
4. 点 **import result**，所选范围在时间线上的原位置应新增四条音频轨，原 clip 保留。试听对比时避免原混音和四条分轨一起播放导致叠加；可将原轨静音。一次 Undo 应移除这一组，Redo 应恢复。
5. 选独立小号素材或分出的 bass / vocals，在 **audio to MIDI** 点 **run analysis**。`onset` 默认 0.50，调高会更严格地筛选音符起点；`min / ms` 默认 80 毫秒，调高会过滤更短音符。改参数后重新运行才会生成新候选，不会立即修改已有结果。点 **import result** 后双击新 MIDI clip 看音符。**新 MIDI 轨需要选择乐器才能发声**，不是原音色复刻；首批只导入音符，不保留弯音。鼓和混合 other 不支持这条音高转录路径。
6. 对短混音运行 **chords**，应看到 C:maj / A:min / N 一类时间区间，低分结果可能显示 `uncertain`。点 **import result** 后会切到 **saved chords**，也可用同名按钮切换。选中一行，修改标签下拉框或起止秒数，再点 **apply**，验证一次 Undo。这里的起止是工程时间线的绝对秒数。分数是原分析相似度，不是正确概率，手工改字不会重新评分。未选中音频 clip 时，saved chords 可查看工程全部已存和弦。

手动分析不需要 GPT/Kimi 密钥。若某种模型未安装或不可用，**run analysis** 应禁用；增高主窗口可查看下栏模型未就绪说明。模型已就绪但没有选中音频 clip 时也不能运行。无需删除已安装模型来模拟此状态。分析面板右侧的 **analysis jobs** 下拉框可回看手动或 Agent 发起的任务；关掉下栏不会取消正在计算的分析。

## 保存、取消与来源变化

- 将含结果的工程另存为新 `.emproj`，关闭、重开。四轨音频、MIDI 音符、和弦标签和原有插件应保留。试一次正常播放。
- 含分析数据的新工程使用 schema 5，0.8.1 会明确拒绝。升级覆盖原 schema 4 文件时保留精确的 `.schema4-<UUID>.bak`；要继续用旧版，优先另存新文件。
- 新建一个分析任务后取消：应能继续操作 DAW，任务最终为 cancelled，无新增轨道。深度学习当前运算段可能不能立即协作退出，宿主仅终止自己的分析进程，不等待在界面线程。
- 生成候选后移动/裁剪源 clip 或改 BPM，再查看旧候选：应提示来源或 tempo 已变化，**import result** 和试听禁用，重新分析即可。外部替换 MP3 后应要求重新导入，不能把旧 PCM 误认成新素材。
- 导入后 Undo，导入按钮应显示 **undone**；恢复用 Redo，按钮回到 **imported**。同一候选不能重复堆出相同轨道。

## Agent 短测

打开 Agent 侧栏，查看固定七类能力是否与当前音频选择、模型就绪状态一致。依次尝试：

- “把选中音频分成人声、鼓、贝斯、其他，先生成候选。”
- “把这个候选导入工程，保持原时间位置。”确认修改卡片后才应出现轨道。
- “把选中的贝斯转成 MIDI，不量化，先预览。”
- “识别选中音频的和弦，给我查看低分部分。”
- 导入和弦后：“把第一段标签改成 C:min，先列出修改。”

分析等待期间只在本地查进度，不反复请求聊天模型。语言模型仍按已有 API 设置工作；音频不上传给 GPT/Kimi。本轮自动 Agent 验收使用模拟语言模型和真实本地分析，因此自然语言理解效果仍需此处人工确认。

## 反馈最有用的内容

说明版本、素材长度/采样率、分析种类、哪一步出现问题、任务状态/完整错误。听感问题说明是分离串音、音符漏检/误检还是和弦错误；界面问题说明窗口大小和操作步骤。播放共存性能请记录实际 ASIO 采样率、缓冲区、轨数和插件负载，不能仅凭“进程隔离”推断绝无爆音。

首批边界：每次最多 600 秒、一个重任务；候选需明确接受；没有自动保存/恢复。鼓分类转录、复杂和弦词表、多模型批量整曲编排和完整识别质量评估留在后续。
