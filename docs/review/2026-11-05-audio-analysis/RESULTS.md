## 管线与性能边界

界面或 Agent 发出命令后，DAW 固定所选音频的来源、采样范围和时间线位置，交给独立本地进程计算；后台校验结果后只展示候选。用户确认导入时再检查工程版本和素材哈希，由控制线程一次写入轨道、音符或和弦；实时音频回调不运行模型、解析 JSON 或访问文件。Agent 在本地等待任务，进度轮询不反复调用聊天模型。

首批每次一个重分析任务，最长 600 秒，CPU 两线程；录音前需完成或取消分析。普通保存可与推理并行，保存的正常素材归档不再误判候选过期。试听使用有界 PCM 环形缓冲，固定 -12 dB，快速切换时取消旧文件校验任务。接受导入仍受文件事务、工程版本和来源检查保护。线程分离不代表 CPU、磁盘或 GPU 干扰为零。

本机 i7-13700H / 约 32 GB RAM / RTX 3050 Laptop 4 GB / 驱动 555.99；固定 7 秒、44.1 kHz 双声道合成输入的最终 Worker 探针为：CUDA 分离 28.62 秒、转录 8.17 秒、和弦 4.68 秒。详细参数、RSS/VRAM 统计与测量方法在 Worker 记录中；这是独立进程离线数据，**没有 ASIO 缓冲或 DAW 同时录放音负载，不是实时性能承诺**。公开授权短音乐也已真实跑通，但没有真值标注，不能据此声称识别准确率。

## 本轮发现并修复的问题

- 初次 MSBuild 路径含 `&` 和 C++ `var` 下标编译问题：改安全源路径联接，修正类型访问；失败构建记录保留。
- 新增 MIDI 轨的一次 Undo 留下空轨：将 Tracktion 延后属性归入同一导入事务，三类真实结果均验证一次 Undo/Redo。
- 普通 Save 被旧文件任务入口拦截：两个入口统一任务准入规则；分析时保存真实通过。
- 保存的正常归档引用被误判为来源修改：独立跟踪控制线程的归档路径，worker 继续使用不可变路径；接受时再校验当前归档内容。分析中保存、ready 后另存和导入均通过。
- 哈希阶段取消显示 failed：统一取消状态；即时取消真实通过。模型 forward 的协作取消延迟另见 Worker 记录。
- 连点试听遗留多个后台哈希任务：新试听取消旧任务，避免失效工作继续读盘；独立只读代码审查发现并修复，组件停止/代次并发测试保留。

中间失败包括 `070740`、`071525`、`073223`、`073926` 真实 E2E；每次改动、构建与原始日志路径保留在 append-only DEVLOG 和 docs/builds，没有将失败改写为通过。
