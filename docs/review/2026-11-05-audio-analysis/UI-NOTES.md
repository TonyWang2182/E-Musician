# 原生分析面板实施记录

状态：已实现；本轮一个候选构建的 CTest 10/10 及原生 UI/试听离线 smoke 通过，已查看生成截图。随后根流程发现并修复原生 MIDI 导入 Undo 问题，当前截图保留为修复前的中间构建证据；UI/试听源码未改变。后续最终二进制验证由总结果记录。设备试听、识别质量与实体交互仍分别验收。

沿用现有黑白等宽工作台。此轮是现有下栏的扩展，未更换设计体系。使用 impeccable 的 context、new-work 与 craft-floor；上下文里旧 PRODUCT/DESIGN 的能力说明低于本轮 CONTEXT、UI_REFERENCE 与已经批准的分析方案。子代理没有独立用户问答通道，直接以已批准的任务和现有设计为输入。

- 顶部 `analyze` 打开或关闭下栏，与 `source` 分开。分析下栏隐藏右侧 inspector 保留宽度，Agent 侧栏可同时打开。
- 三种任务分别为 `separate`、`audio to MIDI`、`chords`。左侧明确源 clip 和源范围秒数；打开前编曲窗的时间选区会与 clip 相交。没有选区时默认整个 clip，超过当前上限会提示缩短范围。
- 分析使用未经过轨道效果的原音频。可用状态来自宿主 Provider 注册信息，未安装模型不会伪装可运行。MIDI 仅面向有音高分轨，显示 onset 和最短音长；明确不支持鼓分类和 pitch bend 还原。
- 右侧任务列表同时显示手动和 Agent 发起的分析。4 Hz 可见轮询；关闭面板停止轮询，不取消用户任务。任务通过同一 `executeRequest` 分发器，不在面板解码音频、加载模型或访问网络。
- 候选结果分页显示，每页 50 条。分离显示 stem 信息及独立试听；仅在宿主声明 `preview_stems` 时启用播放，关闭面板会停止由该面板发起的试听。导入前保持工程不变。
- 来源或 tempo 变更后按工程 revision 回读候选有效性，过期候选禁用导入/试听并提示重新分析；不会只看旧任务的 `ready` 状态。`applied` 表示曾经导入，`present_in_project` 表示当前工程仍含该导入；撤销后显示 `undone` 并提示 Redo，防止同一结果重复导入。无关编辑造成异步应用失败时，仍可重新检查并导入有效候选。
- `import result` 显式接收结果，观察应用任务完成。导入后音符继续使用现有钢琴卷帘修改；和弦可切换 `saved chords`，选中区域后修改标签、起止秒数，通过 `edit_chord_region` 提交并支持撤销。`N` 与 `uncertain` 分开，分数不称为概率。
- 已保存和弦的分数标为原始分析分数，修改标签不会重新评分；完整语义放在行提示中。改标签时保持未改动的精确起止时间，避免显示值四舍五入造成隐式量化。没有选中音频 clip 时，`saved chords` 显示工程全部和弦区域，保留删除来源后的修正入口。
- 原生 smoke 检查只读导航、时间范围映射和窄布局，输出 930×308 与 600×260 面板截图。此测试不会触发真实模型或付费 API。

独立 stem 试听采用 `AnalysisPreview`：低优先级解码线程打开本机已校验 WAV，并在后台重采样到当前设备采样率，写入 65536 帧立体声 SPSC 环形缓存。音频回调只清空、读取并以固定 -12 dB 输出，不访问文件、不分配内存、不释放样本。停止或换 stem 立即使旧 generation 无效；缓存回收留在工作线程。没有活动输出设备时明确拒绝试听。应用退出先移除回调再等待工作线程；异常慢磁盘的退出等待仍是边界，不作零阻塞承诺。

试听的离线 smoke 使用明示合成的 0.1 秒立体声正弦，验证 44.1 → 48 kHz 重采样后的 4800 帧长度、非静音和增益边界、反复开始/停止后的静音，以及无设备拒绝。它不等于实际 ASIO 试听验收。
