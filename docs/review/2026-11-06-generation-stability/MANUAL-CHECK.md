# 0.12.1 人工短测

自动检查与真实短模型检查见 [RESULTS](RESULTS.md)。以下未由用户验收，不需要重复旧版录音/Keyscape 全套测试。

1. 保存并关闭旧窗口，双击 `E:/MusicAgent&DAW/Start E-musician 0.12.1 Stability.cmd`，确认标题 **0.12.1**。旧 0.12.0 入口和归档保留。
2. 打开一个测试工程，记住当前速度和播放头位置；Agent 新对话输入“生成一段温暖的爵士钢琴纯音乐，先让我试听”。预期无需补答 BPM/时长，使用工程速度、默认 20 秒生成候选，尚未新增轨道。试听后明确加入，检查位置，再 Undo 一次撤销导入。云端必须开机并已连接；一个真实 GPT 决策探针通过不能保证所有自由表达都一次成功。
3. 从已生成音频选取约 7–10 秒，在分析下栏选择四轨、快速，运行一次。成功时试听/加入四条轨道；原片段仍在，加入可 Undo。内存不足时应显示可读的失败原因，不能出现需点击的 Python 崩溃弹窗或白屏等待，也不要反复点击运行。
4. 分析过程中检查播放头定位和面板切换；必要时取消。无论成功、失败或取消，工程应仍能普通保存和重开。真实 ASIO 听感、设备共存由这一步人工确认。

若仍出现卡顿或退出，保留生成/分析任务目录及截图，不删除原音频。本轮新增 `worker-launch.json`、`worker-exit.json`、`resource-budget.json`、`process.log`、`fault.log`，可定位进程退出和资源条件。缺少内存的拒绝代表保护生效，不代表分离成功；75 秒六轨高质量原场景尚不能据此声明通过。

目前没有可用的本地/云端 MIR 切换按钮。云端部署准备的进度另见 [阶段计划](../2026-11-06-cloud-mir-stage/PLAN.md)。
