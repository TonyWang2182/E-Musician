# 客观音频检查方法

状态：两份真实生成音频的 CPU 客观测量、BeatThis 估计及云端试听索引已完成，人工听感尚未验收。只读云端原始音频，不复制音频或权重到 E 盘，不调用 GPU、不改变 DAW 或模型服务。结果见 [RESULTS](RESULTS.md)。

## 指标与边界

- 读取原文件的 SHA256、字节数、帧数、真实时长、采样率、声道数、容器及编码格式。测量前后重新核对文件散列和修改时间，避免读到仍在写入的输出。
- 按 20 秒块读取为归一化 float64，统计非有限值、样本峰值、RMS、每声道 RMS/峰值、精确零样本、接近满幅样本和数字满幅样本比例。最后不足 20 秒的块保留实际长度。聚合按样本数加权。
- 静音定义为连续 20 ms 窗内每个声道 RMS 均低于 -60 dBFS；按实际窗长计算时长比例，不把一个低幅采样点直接判成静音。包含非有限值的窗另行记录。
- L/R 相关使用整体配对样本的 Pearson 系数，常量声道时未定义；不能据此证明 pad 宽度、空间设计或混音优劣。
- 样本峰值不是 true peak，RMS 不是 LUFS。接近满幅和数字满幅比例只是疑似削波线索；本次提示词要求 gritty/slight distortion，不能直接据此判坏音质。

## 可选节拍估计

使用已有 `envs/mir-torch`、BeatThis 1.1.0，源码 `b95c8ab0c58c2d9fcfd40508ae8dffbc05ac4f5c`；final0 权重 SHA256 `8c328b45f59d8dd3dff219253ff6a8d6482be57d0133a29140e2febbf8eb8331`。检查固定本地权重，不允许自动下载回退。

只用 CPU、2 个 Torch 线程、1 个 interop 线程，`CUDA_VISIBLE_DEVICES=''`，推理前后断言 CUDA 没有初始化。音频转单声道及 22,050 Hz 由上游预处理完成；使用上游 minimal 后处理，无 DBN、无目标 BPM 约束。子进程上限 240 秒，失败保留日志，不自动重试。

保留所有拍点和小节起始点估计。至少 17 个拍点时，以 8 拍跨度的每拍平均时间之中位数计算原始 BPM，降低 20 ms 帧量化影响；5–16 个拍点时用单拍间隔中位数；不足 5 个不计算 BPM。同时报告单拍中位数结果、拍间隔 IQR/中位数、每 20 秒估计和原始值的半拍/倍拍候选。IQR 比值大于 0.2 仅标为拍间隔变化较多，不是校准置信度。

提示词参考关系固定列为 85 / 170 / 340 BPM，不把模型估计强行归一化到 170。节拍匹配仍是估计，不能证明 Jungle 风格、Amen 切片来源、乐器、MC 内容或六段结构。

## 试听与证据

云端 `results/evaluations/jungle_20261106/analysis/<ace|yue2>/report.html` 使用相对链接引用原音频，不复制、不内嵌 base64。最终 `index.html` 汇总两个报告和原音频入口；通过已有认证的 Jupyter 文件浏览打开，无新端口或公开服务。

报告明确“未试听”。每 20 秒只标绝对时间，不标 Intro/Drop 等主观段落名称。风格、动机、段落顺序、音色和听感需要人工试听另记。相同提示词 SHA `d52750d660e226231a13f846b1ac8ceecbcfb11dc446c13456b0d853333e9678` 由各生成记录证明；分析脚本只引用该来源，不独立判断语义一致性。
