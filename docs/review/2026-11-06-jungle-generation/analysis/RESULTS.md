## 节拍诊断

BeatThis final0 使用 CPU 2 线程，CUDA 没有初始化。模型的拍点本身存在半拍/漏拍混合，下面是原始统计，不是经验证的真实速度。

| 诊断 | ACE | YuE2 |
| --- | --- | --- |
| 跨8拍原始统计 | 123.393 BPM | 173.913 BPM |
| 单拍间隔中位数统计 | 166.667 BPM | 176.471 BPM |
| IBI IQR / 中位数 | 0.9444，变化较大 | 0.9412，变化较大 |
| 拍点数 / downbeat估计数 | 224 / 64 | 274 / 71 |
| 每20秒估计 | 170.21、150.94、97.17、85.11、97.17、113.21 | 87.59、106.43、87.27、173.91、173.91、173.91 |

参考半拍/倍拍关系为 **85 / 170 / 340**。ACE 的 123.393 不能当作全曲真实 BPM；YuE2 的 173.913 也不能证明全曲稳定遵循 170。时间块差异可能是漏拍、额外拍点或半拍解释，不能直接判断发生了变速。每 20 秒只按绝对时间编号，不冒认 Intro、Drop、Breakdown。

YuE2 的 semantic 3000 token 预算触顶，音频是预算截断；ABC 自然结束不能证明音频有自然完整结尾。这一点来自生成记录，不是从音频统计推断。
