## Subsequent cache-location correction

Real end-to-end testing exposed low free space on the system drive. Root authorized a narrow native follow-up after the validation above: `EMUSICIAN_AUDIO_CACHE_ROOT` now selects an MP3 PCM cache root validated by JUCE's `File::isAbsolutePath`, with decoded content in its `audio-v1` child. Unset preserves the old application cache. A bare relative path is rejected rather than resolved or silently redirected. Root-directory, version-directory and cache-entry symbolic-link checks remain in place. Existing cache files were neither moved nor deleted. The release/test launchers use the fixed fully qualified `E:/MusicAgent&DAW/audio-cache`; JUCE's permissive Windows `C:relative` / root-relative classification remains a documented edge case, not a verified strict Windows path parser.

`EngineSessionProjectSmoke` scopes this variable to its own isolated directory and checks relative-path refusal plus actual CBR/VBR decoding under the override. Root's follow-up build `20261106T181155.738154Z-4a8b781c23` passed. CTest `20261106T181327.714250Z-f588fd28c2` passed 11/11 (118.05 seconds test runtime). This is direct evidence that the MP3 fixture used the override, not merely an environment-setting assertion. Small final project/native reports are copied into `evidence/`.
