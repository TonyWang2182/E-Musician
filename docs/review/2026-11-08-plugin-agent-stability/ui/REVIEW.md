## 新发现的插件入口生命期问题

资源库 `activate` 把 `filtered[row]` 的引用交给回调。成功添加设备后 `refreshSnapshot → browser.update → filter` 会清空并重建容器，原调用方还在使用 kind/id；这是实际悬空引用来源。现在激活项和回调均复制到栈，回调即使重建资源库、替换自己或关闭资源库，当前项仍有效。

PluginPanel 的延迟添加执行第三方初始化后，面板可能已被嵌套消息循环关闭；结果回调也可能关闭面板。现在 execute 与 report 返回后均重新检查 SafePointer，且 report 复制后调用。同一类同步 run 路径也做了相同保护，避免打开/移除等命令复用原问题。没有改变引擎、音频回调、插件目录或工程命令语义。

新增真实组件回归：资源库回调同步重建目录后读取原项、替换回调并销毁资源库后继续读取原项；PluginPanel 通过不存在的插件 ID 走真实延迟错误路径，结果回调销毁自身；在延迟执行前关闭面板，确认回调不再触发。这些不加载第三方二进制，不替代真实插件加载验收。第三方初始化内部关闭面板的 execute 后保护仍需真实插件/窗口测试补充。
