# 0.13.6 音频输入修复结果

日期：2026-11-16。状态：已实现、Release及自动回归通过，M-Audio短录音和文件生命周期通过；麦克风来源、听感、厂商面板操作和其他实际声卡待人工验收。

## 修复与范围

旧版设置保存了零个物理输入，但引擎仍显示In1/In2逻辑路由；设置页又没有开启通道的控件。因此选中输入、Arm并不代表硬件正在提供数据。新版明确选择物理通道和mono/stereo配对，Apply后回读实际结果，保留同设备选择，新设备采用按实际通道数限制的前两路默认输入。

固定引擎增加三项补丁，处理Windows回调把活动通道打包、引擎却使用物理索引的差异；仅启用In2也能写入对应样本，空输入清零。映射在设备启动时建立，回调不分配新数组。物理音频目标在切换前先断开并同步发布图，完成后只恢复身份仍匹配的目标；MIDI目标不变。不同声卡的同名Input 1不会静默继承旧轨道。旧工程的未限定音频输入ID需重新选择一次。

Settings增加受能力检查的Driver control panel入口。设备/面板操作禁止与播放、录音冲突；防重入、窗口SafePointer以及返回后的设备重取覆盖嵌套厂商消息循环。厂商窗口仍是其自身界面。本轮没有更改模型、云端、Agent提示词或用户原始工程。

## 失败和修正留档

1. `52244ca3d1`首次configure因新固定补丁尚未应用而拒绝；记录应用`85bfbec236`后configure `6385b40f71`通过。
2. `0a250cf329`构建被主动中止，以补齐换卡前断开音频目标的保护；只终止核对过的自有构建进程树。`4a11d8c4fd`随后完整构建成功。
3. `eb5f8c0a15`的合成重复录音没有推进已排队的Seek，产生静音前缀。固定引擎等待音频同步点，而单线程假驱动只能显式推进；测试现先推进停止回调并断言播放头归零，PCM容差保持不变。不是产品时序修复，也不以此替代真实驱动验证。
4. `5b4346fc6f`已通过六个PCM场景，但测试用`execute("play")`调用不支持的原生编辑命令；改为实际`togglePlay/stop`方法后最终11/11通过。
5. `dce955682d`物理探针误把已完成保存任务的`accepted + job_completion`回复当成失败；实际保存已完成、设置已恢复。只修正探针对异步任务的判定后，`3f4d571d0c`全程通过，EXE未改。

所有尝试均有docs/builds摘要和本地build-logs原始输出；DEVLOG追加保留。构建输出含既有依赖后处理的`pwsh.exe`缺失提示，但最终退出0且EXE/全部测试存在并已执行，不将此提示隐去。
